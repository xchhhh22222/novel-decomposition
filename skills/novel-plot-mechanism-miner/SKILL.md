# 剧情机制横向拆解器

## 模式路由

- 单书抽取：先读取 [references/schema.md](references/schema.md)。
- 横向近邻、聚类与 QA：再读取 [references/clustering-and-qa.md](references/clustering-and-qa.md)。
- 结构校验：运行 `python scripts/validate_outputs.py <jsonl或目录> --kind <per_book|nearest_neighbor|cluster|qa|handoff|gap>`；跨书必须额外提供 `--expected-books`、`--all-books-complete` 和 `--completion-manifest <per_book/gap.jsonl>`。

## 单一职责

一本书的 `per_book` 记录使用 `mechanisms[]` 承载多个独立机制；不得只记录一个代表性机制而覆盖其它已证据化实例。

本 Skill 不回答“这本书发生了什么”，而回答：

> 某类剧情为什么能够反复运转？什么条件启动，谁承担什么运行角色，通过哪些信息、资源、选择和约束传导，怎样升级并产生结果，运行后状态如何改变，以及为什么这套结构还能再次工作并允许变化？

剧情机制必须从具体实例中抽象，但不能把单次事件、单条线路、某个阶段或题材标签直接升级为机制。有效候选至少要能说明可观察的启动前提、运行步骤、路径选择、约束、结果、状态变化和再次运行条件。

本 Skill 不负责：

- 章节摘要、事件流水账或单场戏复盘；
- 某一条剧情线的完整生命周期、线路支付或下一入口；
- 长篇 arc 的边界、阶段目标、阶段转折和分卷收束；
- 卷名、地图名、比赛名、考试名或题材标签的分类；
- 世界规则、制度、组织、资源循环和地图因果的完整拆解；
- 境界、技能、装备、战力与成长循环的完整拆解；
- 金手指的输入、处理、输出、限制和成长模型；
- 人物性格、人物功能组合、关系发动机或人物卡；
- 逐章 reader emotion、情绪词统计或情绪曲线本身；
- 可直接入库的正式机制卡、正式素材卡或总索引；
- 为了凑齐候选而补造未被证据支持的机制。

相邻专项只能提供 interface/evidence。机制专项不复制相邻专项的完整业务对象。

## 核心运行对象

以下对象是观察维度；具体字段、枚举、记录 envelope、聚类规则和验证脚本已在当前 `references/schema.md`、`references/clustering-and-qa.md` 与 `scripts/validate_outputs.py` 冻结。

### mechanism_identity

说明这是什么可复用的剧情运行结构、解决什么叙事任务、在什么实例范围内被观察，以及它与相近候选的差异。身份必须描述运行方式，不能只写“比赛”“考试”“追杀”“打怪”“秘境”“打脸”等表面名词。

### trigger_conditions

说明哪些前置状态、承诺、压力、权限、关系、资源、信息或风险满足后，机制才会启动。一次偶然事件发生不自动构成机制触发；触发条件必须可从章节、阶段或实例证据中回查。

### actors_and_roles

记录参与者在机制中的运行角色，例如施压、响应、试探、验证、阻断、竞争、见证、兑现或改变条件。角色是机制中的功能位置，不是人物性格标签，也不替代 character-function-miner 的人物功能判断。

### inputs

记录机制运行所需的信息、资源、身份、规则、风险、关系、时间窗口、权限或读者期待前提。世界观规则、成长资源或金手指能力只能作为输入或接口证据，不在这里重建其完整系统。

### operations

还原机制如何实际运转：压力如何传导，参与者如何响应，信息或资源如何流动，哪一步验证前提，哪一步把结果推向下一步。不得只罗列事件名称，必须写出结构动作之间的关系。

### decision_points

记录真实会改变运行路径的选择点，包括谁在何处面临哪些可行路径、选择如何改变风险、资源、信息、关系、权限或后续结果。没有路径分叉的普通动作、被动受伤或单纯发生的反转不能自动算 decision point。

### constraints

记录限制机制的规则、资源稀缺、时间窗口、权限门槛、身份边界、关系代价、信息不对称或失败成本。约束必须解释它如何限制选择、改变运行方式或制造可复用张力。

### escalation_logic

记录机制怎样升级、变形、扩张、反转或提高代价。升级应说明压力传导、信息差变化、资源门槛、角色关系、权限变化、公开程度或结果 stakes 的结构变化；不能只写敌人更强、数值更高、场面更大。

### outputs

记录一次机制运行产生的可观察结果，例如公开认知改变、资源归属变化、权限验证、关系动作、任务结果、风险转移、失败后果或新的选择空间。outputs 是一次运行结果，不等于整个机制已经被证明可复用。

### state_transition

记录运行前后的系统状态差异：目标、资源、身份、关系、认知、权限、风险、势力平衡、地图入口、承诺或读者期待发生了什么可观察变化。不能只写“事件结束”“进入下一章”或“进入下一卷”。

### repeatability

解释为什么机制在另一组实例中仍然能够成立：哪些触发条件、运行角色、约束、压力传导和结果逻辑必须保留，哪些变量可以替换。复用必须依赖可观察条件，不是“作者以后还能再写一次”，也不能用单次实例自行证明。

### variation_points

记录机制重复运行时可以变化的参数，例如人物角色、资源类型、信息差、权限门槛、地图、时间压力、公开程度、失败成本、兑现对象或结果规模。变化必须保留核心运行结构，同时能解释为什么不会机械重复。

### failure_modes

记录机制无法启动、运行中断、被识破、资源不足、角色拒绝、约束改变、选择失败、结果反转或结构失效的条件。不能只写“主角失败”，要说明机制哪一环断裂、谁承担后果以及是否还能重新启动。

### payoff_path

记录前置压力、承诺、输入和决策如何经过机制转化为结果或回收。payoff_path 不等于 outputs：它还要说明读者可观察的兑现证据、兑现对象、选择验证、代价回响或后续余震如何完成回收。

## 机制与相近对象的硬区别

以下边界不可放宽：

- **机制 ≠ plotline**：plotline 追踪一条具体线路的 trigger、goal、阻力、节点、选择、代价、payoff 和生命周期；机制提取多个实例背后的可复用运行结构。
- **机制 ≠ arc**：arc 组织长篇阶段的目标、压力、推进、转折和收束；机制可以跨多个 arc 重复，不负责划 arc boundary。
- **机制 ≠ chapter summary**：章节事件列表只能提供实例证据，不能替代机制的运行结构。
- **机制 ≠ trope/tag**：题材、宣传语、场景名和标签不是机制身份。
- **机制 ≠ 比赛/考试/追杀/打怪/秘境**：表面场景只能是实例容器，不能单独证明机制相同。
- **机制 ≠ 单次剧情实例**：一次实例不能直接升级为 mechanism；至少要有重复运行条件或跨实例结构证据。
- **机制 ≠ 世界规则本身**：世界规则是可能的 input 或 constraint，机制还必须说明人物如何利用、抵抗、验证或改变它。
- **机制 ≠ golden-finger mechanism**：金手指负责能力系统的输入、处理、输出、限制和成长；本 Skill 只观察它怎样参与剧情运行。
- **机制 ≠ character function**：人物功能说明人物为什么存在；本 Skill 只记录参与者在某次运行中承担的 role/interface。
- **机制 ≠ 简单 A→B 因果链**：单纯“发生 A 所以发生 B”没有可复用的触发、操作、约束、决策、升级和状态转换说明，不足以成为机制。
- **事件重复 ≠ mechanism repeatability**：重复出现相似事件不等于结构可复用；必须解释再次工作的条件与可变化的变量。

表面事件不同但 trigger、角色、输入、操作、约束、决策、升级、输出和状态转换的运行结构相近，可以成为同类机制候选。表面事件相同但这些关键关系不同，不得强行归并。不能因为两本书都有“比赛”“任务”“追杀”“升级”就判定机制相似。

## 证据边界与输入

严格遵守：

1. `skills/novel-dna-orchestrator/SKILL.md`；
2. `skills/novel-dna-orchestrator/references/horizontal-specialist-contract.md`；
3. `skills/novel-dna-orchestrator/references/integration-and-qa.md`。

输入必须来自 orchestrator 冻结的批次包，至少说明目标书、章节/阶段范围、允许来源、上游 QA、相邻专项接口、已知缺口和禁止输出。不得自行扩大书单、章节范围、实例范围或来源，不得用一本书的机制实例补齐另一本文本。

证据优先级：

1. 已通过 QA 的章节事实、实例动作、选择、结果和状态变化；
2. 已确认的线路、阶段、开篇、人物、情绪、世界、修炼和金手指接口证据；
3. 已存在的阶段/线路资料，仅作定位和交叉核验；
4. BOOK DNA、章节索引和既有聚类，仅作导航；
5. 原文回查，仅在触发、路径分叉、约束、复用条件、失败模式、兑现或状态变化不清时使用。

书名、简介、章节标题、地图名、境界名、题材标签、宣传语和模型记忆不能独立支撑 mechanism 结论。证据不足时保留 `UNKNOWN`、`partial`、`gap` 或 `HOLD`，不能用“通常这种套路会……”补造运行结构。

每个机制候选至少应能回答：

- 什么条件使机制启动；
- 谁在机制中承担什么运行角色；
- 机制需要哪些输入并受哪些约束；
- 哪些操作和信息/资源流让它继续运转；
- 哪些 decision points 会让路径分叉；
- 机制如何升级、反转或提高代价；
- 一次运行产生什么输出和状态变化；
- 为什么在可观察条件满足时还能再次工作；
- 再次运行哪些变量可以变化；
- 哪些条件会使机制失效、被打断或反转；
- 压力、承诺和选择如何最终形成 payoff 及其可见证据。

## 与相邻专项的分工

- `novel-plotline-miner`：负责某条具体剧情线的生命周期；本 Skill 只抽取多个实例背后的可复用运转结构。
- `novel-arc-structure-miner`：负责长篇阶段组织；本 Skill 可以跨 arc 重复，但不负责阶段边界、阶段目标或阶段收束。
- `novel-opening-miner`：负责开篇窗口和十二类开篇对象；本 Skill 只引用某机制在开篇的首次起效或验证。
- `novel-character-function-miner`：负责人物功能组合和关系发动机；本 Skill 只把人物作为运行 role/interface。
- `novel-chapter-emotion-miner`：负责逐章 reader emotion、蓄压、兑现和余震；本 Skill 只引用情绪作为运行效果和 payoff 证据。
- `novel-worldbuilding-miner`：负责世界规则、制度、资源和地图因果；本 Skill 只使用其作为 input/constraint，不复制世界观模型。
- `novel-cultivation-system-miner`：负责修炼、战力、成长和资源循环；本 Skill 只引用成长规则作为门槛、资源或 output。
- `novel-golden-finger-miner`：负责金手指能力系统；本 Skill 只观察外挂如何参与剧情运行，不复制外挂的 input/process/output 正式模型。

如果机制判断必须依赖相邻专项尚未确认的完整业务对象，只保留 interface、证据引用和依赖缺口，不越界代替相邻专项下结论。

## 运行流程

1. **冻结输入**：登记批次、目标书、章节/阶段范围、允许来源、上游 QA、实例范围、已知缺口和禁止输出；
2. **收集实例**：只记录有章节或阶段证据的剧情实例，不以单次场景名称直接命名机制；
3. **识别触发与输入**：还原启动条件、角色前提、资源、信息、身份、规则、风险和关系门槛；
4. **还原运行操作**：追踪压力传导、角色响应、信息/资源流和验证步骤；
5. **寻找决策点与约束**：确认哪些真实选择改变路径，以及规则、权限、时间、资源和代价怎样限制选择；
6. **提取升级逻辑**：说明机制如何提高压力、扩大范围、改变信息差、调整角色关系、提高权限门槛或反转结果；
7. **确认输出与状态变化**：区分一次运行的结果、可见兑现和运行前后的系统状态差异；
8. **检查复用条件**：验证至少两个实例之间哪些结构稳定、哪些参数变化，以及为什么第二次运行仍然成立；
9. **提取变体与失效模式**：记录可替换变量、机械重复风险、无法启动、被打断、失败和反转条件；
10. **还原 payoff path**：核对前置压力、承诺与选择怎样获得可观察的结果、他人反应、代价回响或后续入口；
11. **单书 QA**：检查实例证据、机制边界、重复性、变化点、失败模式、相邻接口和 `UNKNOWN/gap/HOLD`；
12. **跨书比较**：全部目标书完成单书提取与 QA 后，比较机制的运行结构、差异边界和变体，不按表面场景聚类；
13. **人工交接**：输出 candidate、实例证据、最近邻、聚类候选、争议、缺口和待确认决策，不自动入库。

## 横向比较原则

跨书比较的对象是机制如何运行，至少比较：

- 触发条件和输入是否承担相近结构功能；
- 角色如何施压、响应、验证、阻断和兑现；
- 操作、信息流、资源流和 decision points 如何组织；
- constraints 如何限制路径并制造张力；
- escalation 如何改变压力、权限、风险、公开程度或结果；
- outputs、state transition 和 payoff path 如何连接；
- repeatability 依赖哪些不变量；
- variation points 如何产生不同实例；
- failure modes 如何打断、反转或改变机制。

“都有考试”“都有比赛”“都有追杀”“都有任务”“都有打怪”不能单独支撑近邻或聚类。相同事件如果运行结构不同，应保持区分；不同事件如果运行结构相同，可以保留同类候选并记录表面差异。证据不足时使用 `insufficient_evidence` 或 `HOLD`，不强行归类。

## 交付、状态与写入边界

默认输出位置（仅在用户授权后落盘）：

```text
素材库/DNA素材/09_剧情机制/per_book/
素材库/DNA素材/09_剧情机制/candidate/
素材库/DNA素材/09_剧情机制/qa/
```


每个专项批次固定规划五类交付：

1. `per_book`：单书机制实例、运行结构、复用条件、变体和失败模式证据包；
2. `nearest_neighbors`：按运行结构、差异边界和复用条件比较的近邻记录；
3. `clusters`：机制母型、子型和变体的候选聚类；
4. `qa`：实例覆盖、重复性证据、边界、缺口、争议和阻断项；
5. `handoff`：交给人工审核的机制候选、实例证据、近邻和决策点。

必须遵守：

- 所有结果只能是 `candidate`，不得生成或升级为 `active`、`deprecated` 或正式素材卡；
- 每条抽象结论带章节或阶段证据；证据不足显式保留 `UNKNOWN`、`partial`、`gap` 或 `HOLD`；
- `nearest_neighbors` 与 `clusters` 必须等待全部目标书完成单书提取和 QA，并通过 cross-book completion gate；
- 不写正式素材库、总索引、章节事实、分卷资料或其它正式产物；
- 不根据书名、章节名、简介、题材标签、场景名或单次实例补造机制；
- 不修改相邻专项的 schema、索引、情绪记录或正式候选；
- 任何状态升级、schema 变更、机制合并、跨专项合并或正式入库都交给上位总控和人工审核。

## 禁止事项

- 把一次比赛、考试、追杀、打怪、秘境、误会、测试或公开结果直接命名为机制；
- 把单条 plotline 的目标、高潮、payoff 或下一入口直接当作机制对象；
- 把 arc 的阶段边界、高潮或结算直接当作机制对象；
- 把章节顺序、事件数量、地图变化或敌人升级直接当作机制升级；
- 把简单 A→B 因果链、单次反转或人物性格标签包装成可复用机制；
- 把世界规则、金手指、修炼体系或人物功能的完整模型复制进本专项；
- 没有第二个实例或明确复用条件时，擅自宣称 repeatability；
- 没有真实路径分叉时，虚构 decision point；
- 用“敌人更强”“数值更高”“规模更大”替代 escalation logic；
- 用“事件结束”“进入下一章”替代 state_transition 或 payoff_path；
- 因为表面场景相同就强行合并不同运行结构；
- 因为表面场景不同就忽略相同的运行结构；
- 在所有目标书完成前建立跨书近邻或聚类；
- 把 candidate 写成 `active`、`deprecated` 或正式素材卡；
- 为填满对象补造触发条件、输入、约束、决策、复用条件、失败模式或兑现证据。

## 交付前验收

每次交付前至少确认：

1. mechanism_identity 描述可复用运行方式，不是题材标签；
2. trigger_conditions、inputs、actors_and_roles 和 constraints 有实例证据；
3. operations 记录机制如何运转，不是事件列表；
4. decision_points 是能造成路径分叉的真实选择；
5. escalation_logic 不等同于数值增加或敌人升级；
6. outputs 与 state_transition 分开，payoff_path 说明前置压力如何完成回收；
7. repeatability 有可观察条件，variation_points 与 failure_modes 可追溯；
8. 一次实例、plotline、arc、summary、trope/tag、世界规则、金手指和人物功能边界清楚；
9. 与八个相邻专项只保留 interface/evidence，不发生职责泄漏；
