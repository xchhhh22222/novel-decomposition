# 大小高潮脉络与新书剧情筛选

## 为什么另建视图

现有 `arcs[].arc_climax_or_resolution` 只说明阶段如何收束，不能直接回答“第几个大高潮、靠哪些小高潮蓄压、它怎样逼出下一高潮”。本视图从已核验的 arc、plotline、章节情绪和必要原文回查派生；不得改写既有 canonical arc 记录，也不得把候选写成正式套路卡。

## 判定

- **小高潮**：一个局部承诺被可见兑现或反转，至少有铺垫、主角选择/行动、阻力、结果及人物/制度反应；可发生在一个章节，也可跨若干章。不能仅凭打斗、升级或章末悬念判定。
- **大高潮**：多个小高潮和主要线路汇合，阶段主矛盾发生可验证的胜负/失败/转向，并改变主角的身份、权限、资源通道、关系格局或下一阶段目标。大场面本身不够。
- **脉络边**：写清前一节点留下的收益、债务或风险如何导致下一节点；不能只按章节顺序连线。
- **覆盖边界**：只对已拆章节判定。若来源仅 1—60 章，只能称“已拆范围内的大高潮”，不可称全书第一、第二大高潮，除非更早/更晚文本也有证据。

## 单书交付格式（对话或单独候选视图）

经用户明确授权写入素材库时，默认将每本书的派生记录存于 `DNA素材/08_篇章结构/derived/BOOK_XX_climax_map.jsonl`；未授权只在对话展示。每条 JSONL 顶层保留 `status: candidate`、`record_type: climax_map`、`record_id`、`book_id`、`title`、`chapters_covered`、`qa_status`、`confidence`、`unknowns`、`spine_summary`、`nodes`、`evidence_refs`，便于开书检索；这不是既有 arc 的 canonical schema，也不自动生成 active 卡。

先给 `书ID｜已核验章节范围｜QA｜未知区间`，再列按因果顺序的节点：

`节点ID｜大小/未决｜章节或阶段｜承诺/蓄压｜主角目标与主动选择｜阻力/代价｜可见兑现及旁观反应｜状态变化｜指向下一节点的因果｜证据引用｜置信度`。

最后用 5—10 句总结：开篇承诺 → 2—5 个关键小高潮 → 第一大高潮 → 余波/新门槛 → 第二大高潮（若覆盖）。未观察到第二高潮就标 `UNKNOWN`，不能补成常见套路。小高潮数量随证据而定，不为填表硬凑。

## 为新书选剧情

从单书脉络中提取的是“剧情功能链”，不是照搬事件链。先核对新书现有世界规则、金手指输入、主角阶层、女主和反派的自主目标，再筛选 1 个最适配或 A/B/C 三案。每案注明来源与覆盖范围、可借鉴的蓄压→兑现结构、要改造的冲突对象/触发原因/资源/地图/人物/代价/结果，以及与本书开篇和 50 章阶段目标的衔接。至少改造其中三项，且不得复用参考书的专名、标志性场面和完整连续事件链。

选定第一大高潮后倒推前约 50 章：终局状态差 → 必须提前建立的资源/能力/关系 → 小高潮与公开验证 → 开篇承诺。第二大高潮只能由第一高潮的余波、新权限或新债务自然推出；不要预先机械分配每章情节。用户未确认时均标候选。
