# Emotion Arc Weaving V2 — optional research mode

Use only when the user explicitly requests the research architecture or supplies an approved V2 research input. It is not the default Planner schema and does not replace old validators.

## Route

Keep `E0/E1/M0/D1–D4`. Insert optional E2 and E3 between E1 and M0:

- **E2 — macro arc design:** define the stage reader promise, observable settlement, irreversible change, and its connection to the series promise.
- **E3 — weaving and handoff:** track independent small lines, causal or non-causal event relations, dominant-line changes, the old payoff contract, and a new arc trigger.

Then select RMF only when actually available, derive 02–09 slots, verify source/interface/current compatibility, build original adapters, and execute the existing Story Spine and climax-backplanning process.

## Executable research entry

The minimal adapter accepts a structured original-design brief. It derives all 02–09 functional slots before querying the existing shared-library search command:

```text
python scripts/run_emotion_arc_v2_research.py \
  --brief <pilot-input.json> \
  --output-dir <research-output> \
  --material-snapshot-repo <frozen-git-repo> \
  --material-snapshot-commit <full-commit> \
  --material-package-subdir packages/shared-dna-library/v1.0.0
```

For an exact old-path regression, add `--disable-emotion-arcs`; no E2/E3 or material assembly fields may leak into that result. The snapshot route exports manifest-declared Git blob bytes so Windows checkout line-ending conversion cannot bypass or falsely fail the existing package integrity gate.

Outputs are research-only: `functional-requirements.json`, `material-assembly.json`, E2 macro table, E3 active-line/weave/handoff tables, nine-stage `story-spine.json`, the combined plan and its validation report. A resolved source means a provenance-verified retrieval candidate, not semantic compatibility approval. Each selected slot remains `CANDIDATE_NEEDS_SEMANTIC_REVIEW`; a miss remains an explicit gap.

## Four planning views

1. **Promise/macro table:** series promise, macro IDs, starts, settlement contracts, irreversible changes.
2. **Active-line table:** expectation, reader knowledge, pressure, character choice, paid/unpaid state, delay risk, role, macro membership.
3. **Weave/handoff table:** event, participating line IDs, relation type, before/after, causal evidence, old contract, new promise.
4. **DNA assembly sheet:** beat need, 02–09 slot, source candidate and provenance, interface, adaptation, compatibility, gap.

The views reference stable IDs and do not repeat four versions of the plot.

## Compatibility rules

- `PLOTLINE` still supplies trigger, goal, resistance, nodes, choices, costs, payoff, state change, and next entry.
- `STORY_ARC` still organizes plot stages. A macro emotion arc is a many-to-many reader-promise overlay.
- `SUPPORTED` is reserved for eligible formal components. A research retrieval is `CANDIDATE_NEEDS_SEMANTIC_REVIEW` until a human compatibility decision; missing material is `MATERIAL_GAP`; new logic is `ORIGINAL_DESIGN`.
- Source fact, functional abstraction, and original design must be separately labeled. Never copy source names, unique objects, or a connected event chain.
- B may start before A closes, but A keeps its observable payoff contract. If overlap or settlement is unverified, retain HOLD.

## Long-form and writing boundary

Increase resolution only for near chapters. Later ranges remain macro constraints and sustainability tests. A pre-writing state packet may read `active_macro_arcs`, `active_emotion_lines`, `pending_payoff_contracts`, reader knowledge, constraints, chosen story beats, and adapter refs. Drafts produce candidate deltas only; official state changes still require the existing user-confirmation process.
