# 素材先行的开书组装

用于用户希望 Agent 主动提供故事方向，而不是只对用户方案做修订时。此模式先选择可写的高潮与人物关系，再倒推章节；不要求立即产出 300 章。

## 五类输入，分别取证

1. 带日期的新书榜样本：只用实际读过的章节判断开篇承诺、首次兑现和前 10 章节奏；旧快照要标日期，不当作实时榜单。
2. `DNA素材/02_金手指`：优先对照 per_book 的输入、处理、输出、成本、首次验证与资源循环，再看 cluster 的最近邻；允许选成熟母型或低创新变体。
3. `DNA素材/03_世界观` 与 `04_修炼体系`：寻找持续制造稀缺、敌人、制度分配和成长验证的规则链，不把参考书专名照搬成新书事实。
4. `DNA素材/05_人物功能与标签` 及人物个体卡：至少给出一位女角色与一位反派的自主目标、筹码、行动、关系转折；只有功能位而无个体卡时标记缺口并回查章节证据，不用“校花”“恶少”代替人物。
5. `DNA素材/08_篇章结构`、高潮脉络和章节情绪：定位大高潮的蓄压、触发、兑现、状态变化与下一入口；小高潮要服务于同一大高潮，不按章节数机械平均。

按模块运行 `search_dna_candidates.py --include-per-book --modules <module>`，一次只读少量命中记录。默认不只查正式套路卡，也不因为 cluster 是 candidate 就完全忽略其有证据的单书来源。索引结果为空或摘要空白时打开对应 per_book，不让检索格式问题变成“素材不存在”。

女主、长线反派候选卡分别检索 `05_人物功能与标签/derived/heroine/`、`derived/long_arc_villain/`；大故事线中的连续对抗、主角收益与反派计划受损检索 `08_篇章结构/derived/major_storyline/`，全书大小高潮仍查 `derived/` 的高潮图。脚本用 `--include-per-book` 递归检索这些派生目录。目录尚空时说明“未回填”，继续使用既有逐书功能/arc 与章节事实构思，不把不存在的卡写成已经审核通过。

## 先出可选择的剧情包

每案至少包含：一句话卖点；可复用金手指原型及其剧情输入；世界规则与资源/身份阶梯；女主和反派的自主行动；第一大高潮的具体冲突、可见胜负与不可逆收益；第二大高潮如何由第一高潮余波而来；三个最主要的相似性或逻辑风险。A/B/C 至少在高潮目标、主要阻力、金手指资源入口或人物关系发动机中的两项实质不同。

明确区分 `来源事实`、`抽象机制`、`新书候选`。引用到 book_id、章节范围与 QA 状态；覆盖只到第 60/120 章的书不能声称掌握全书高潮。用户选定剧情方向之前，不把候选写成正式设定，也不先倒排逐章。

## 倒推高潮

先写高潮之后主角得到的战力、资源、身份、关系、信息和新责任，再写高潮前必须成立的敌人优势、主角缺口、人物选择与读者期待，最后安排若干小高潮逐步取得条件。每个小高潮至少改变一项状态，并使第一大高潮更难或更有意义。第二大高潮必须由第一高潮的公开结果、代价、敌方反应或新权限引出，不能只换地图和更强怪。

成熟金手指机制可以保留运行公式；不要复用原作的角色组合、专名、独特表达和连续事件链。轻微改动也要检查它在新世界里如何获得输入、为什么主角必须行动、如何公开验证、什么会让它失效。若这些接口对不上，换原型而非勉强包装。
