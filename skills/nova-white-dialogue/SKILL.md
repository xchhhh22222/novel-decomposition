# Nova White · 都市高武对白引擎

## 目标

让读者相信三件事：人物真的在场；他此刻确实会这样说；换一个角色，这句话便不成立。

对白服务人物当下的利益、关系和情绪，不替作者朗读设定。句子漂亮的优先级低于人物真实、信息边界和场景推进。

## 事实与职责边界

按以下顺序处理事实：

1. 用户当前明确要求与纠正；
2. 当前项目的 `AGENTS.md`、正式总纲、世界观、人物库和已确认正文；
3. 当前章纲、场景目标与用户提供的原文；
4. 本 Skill 的写作方法。

本 Skill 的方法不能覆盖项目事实。人物不知道的事不能借对白说出；待定身份、技能、势力、数值和关系走向不得被对白暗自写死。信息不足时，保持必要模糊或使用可替换占位，不凭空补出长期设定。

只负责对白、与对白直接相连的动作、停顿、表情、空间关系和节奏。持续战斗中的距离、攻防、伤害与战术服从章纲或战斗设计；本 Skill 只调整人物在战斗中何时说、说多少、因身体状态说成什么样。

## 选择工作模式

根据请求自动选择，不必要求用户先声明模式：

- `WRITE`：依据人物、关系、场景目标与结果生成对白场景。
- `REWRITE`：保留既有剧情事实、信息量、人物立场、行动结果和伏笔，只改对白及其紧邻的非语言互动。不得借润色改变谁赢、谁知道什么或谁作出决定。
- `AUDIT`：不改原文，定位失声纹、解释过量、信息越界、动作模板化、关系表达不足和节奏问题；按影响排序并给局部修正方向。

用户只要求点评时不得擅自重写；用户要求改写时直接给可替换文本，不把长篇分析混入正文。

详细交付格式见 [references/output-contracts.md](references/output-contracts.md)。

## 最小上下文

有项目文件时，先读取项目指令，再只定位以下必要信息：

- 本场登场人物的正式人物条目；
- 当前场景目标、冲突和必须抵达的结果；
- 前一场或承接段落，必要时读取最近正文以校准声纹；
- 与对白直接相关的能力、制度、资源和知情边界。

不要为了改一场对白读取整部小说。正式资料与原文冲突时先指出；`REWRITE` 不替用户裁定冲突。

生成前在内部建立简短场景矩阵，不向用户输出推理过程：

| 维度 | 每名主要说话者需要确认的内容 |
| --- | --- |
| 身份 | 年龄、身份、实力或地位、社会经验、表达能力 |
| 关系 | 亲疏、权力差、旧账、依赖、竞争或试探 |
| 目的 | 此刻想让对方做什么、相信什么、放弃什么 |
| 信息 | 知道、不知道、误以为、想隐瞒、可能撒谎的内容 |
| 情绪 | 情绪类型、强度、是否愿意让对方看见 |
| 声纹 | 句长、语速、直白度、礼貌度、幽默感、压力下变化 |
| 场景锚点 | 可真实操作的道具、任务、距离、出口、噪声或时间压力 |

缺少完整人物卡时，从已有原文提取稳定特征，只做低风险差异化，不临时发明口头禅或背景故事。

## 核心生成模型

重要交流按以下结构思考：

`表层台词 + 当下目的 + 没说出口的内容 + 对方反应/状态变化`

每个主要人物都应有自己的目的，目的可以一致、冲突或错位。允许敷衍、反问、回避、沉默、抢话、答一半、说错、装作不知道和用行动回答。不要默认采用“提问—完整正确回答—点头理解”的标准问答。

对话中可以有不直接推进剧情的短句、重复和半句话，只要它们在建立关系、压力或现场感。不要把所有台词修成完整书面句。

## 都市高武适配

保持“现代社会中的高武”而非宗门玄幻腔：学生、教练、校方、协会、军方、研究人员和高阶武者应带有不同制度身份与语言习惯。排名、积分、兽晶、任务、训练、伤势和技能构筑等信息要成为人物争取资源或作出决定的筹码，而不是说明书。

特别注意：

- 年轻角色可直接、嘴硬、吐槽、说废话或不擅长表达，但不要所有人都用同一套网络梗。
- 教练优先用演示、纠错、命令和追问教学；只有当人物需要理解并立即行动时才解释原理。
- 强者的压迫感优先来自选择权、停顿和后果，不来自长篇自夸。
- 阶段性对手应有自洽目标与体面，不自动变成低智辱骂工具。
- 资源谈判应表现需求、底价、试探和让步；不要把数字逐项报表化。
- 战斗高压时台词更短，并受呼吸、疼痛、距离、噪声和配合窗口约束。
- 隐藏身份与秘密线必须遵守双方知情边界，可用双关与回避，不用作者全知泄密。
- 单女主或克制感情线优先用特殊待遇、记住小事、并肩选择、秘密边界和口是心非推进，不用突兀告白或多人暧昧抬轿。

需要具体场景策略时读取 [references/urban-high-martial.md](references/urban-high-martial.md)。

## 动作与非语言互动

动作必须至少承担一种作用：情绪、关系、剧情、空间或潜台词。优先使用场景中本来就存在的行为，例如调枪、压腿、翻训练记录、归还腕表、推回申请表、检查护具、清点兽晶、封闭舱门。

不要为了替换“说道”给每句话硬塞动作。自然节奏可以是几句纯对白、一个动作、一次沉默、环境打断，再继续交流。对白标签不是禁词；当说话者无法自然辨认时，用简洁标签比堆砌文学动作更好。

避免动作翻译和双重表达：动作已经表现愤怒，就不要再写“显然十分愤怒”；动作已经拒绝，就让台词补充条件或后果，不要再重复“我不同意”。

详细原则与负面模式见 [references/dialogue-craft.md](references/dialogue-craft.md)。

## 声纹设计

核心角色应具有稳定但可变化的声纹。声纹不是口头禅，而是角色在取词、句长、回答方式、礼貌程度、玩笑方式、信息保留和高压反应上的选择规律。

建立新角色、多人场景或声纹混淆时读取 [references/voice-cards.md](references/voice-cards.md)。隐藏人物名后，核心角色的多数关键台词应仍能凭关系和表达策略区分；不要追求每一句都能脱离上下文单独辨认。

## 信息释放与场景闭环

一轮对白通常只承载一至两个真正的新信息。双方共同知道的内容不应为读者完整复述，除非一方正在质疑、施压、纠错、留证或故意重定义它。

一个重要对白场景结束时，至少改变一项：决定、关系、信息、资源、身份判断、风险、行动方向或读者期待。日常闲聊可以主要承担关系与生活质感，但不能长期原地踏步。

## 完成前 Dialogue Pass

逐项检查并只做局部修正：

- 是否存在标准问答、设定播报或双方共同信息复述；
- 是否所有人物都理性、克制、解释完整，或共享同一声纹；
- 是否有人说出了其无权知道、不会承认或没理由说出的内容；
- 是否连续使用“首先、其次、最后”“这意味着”“也就是说”“只有……才能……”；
- 是否每句前都塞动作，或反复点头、皱眉、挑眉、摸鼻子、瞳孔收缩；
- 是否直接解释情绪，或动作与台词表达完全重复；
- 是否符合场景空间、身体状态、人物地位与现代都市高武语境；
- 是否在不知不觉中改变了剧情事实、战力、资源、关系边界或隐藏身份。

本地文件可用 `python scripts/dialogue_audit.py <文件或目录>` 辅助定位高频风险。脚本只提供线索，不能用计数替代语境判断，也不能自动改写正文。
