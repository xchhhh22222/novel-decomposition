# 番茄网文素材整理器

## 目标

把原始拆书证据整理成可追溯、可去重、可按目标情绪低成本检索的跨书公共资产。先确定希望读者产生的主情绪及其兑现强度，再检索能制造该情绪的铺垫、冲突、兑现与余震机制。素材只提供结构启发，不能成为当前小说的事实，也不能覆盖项目 `AGENTS.md`、总纲、世界观、人物库或已确认正文。

素材库默认应位于独立的共享目录，不附属于某一本小说。路径解析优先级：用户本次指定的绝对路径 > 创作任务配置的 `shared_library_root` > 已确认的公共库路径。不存在已确认共享路径时先请求路径，不得因为当前目录存在 `素材库/` 就自动把它当公共库。

公共库路径应在项目配置或当前任务中确认；文档中统一记为 `<SHARED_LIBRARY_ROOT>`。

## 模式路由

- **新增或整理素材**：读取 [references/card-schema.md](references/card-schema.md) 与 [references/ingestion-workflow.md](references/ingestion-workflow.md)。
- **素材检索或素材支撑的章纲方案**：读取 [references/retrieval-and-scoring.md](references/retrieval-and-scoring.md)。
- **素材库审计或重构**：读取上述三个 reference；先审计，后提出可复核的修改范围。
- **仅核验索引是否过期**：直接运行 `scripts/material_library.py audit --library <素材库路径>`，不必读取 reference。

不要为了保险加载所有 reference。用户同时要求新增素材和立即检索时，才读取全部相关文件。

## 不可省略的原则

1. 一张套路卡只表达一个可独立迁移的主机制；两个机制可以组合使用，但不能因为出自同一段剧情就塞进同一卡。
2. 来源章节、出现次数与支持等级必须有可追溯证据。缺少证据时标为待确认，不得补造。
3. 跨书出现频率只代表成熟度，不代表当前小说适配度或商业价值。
4. 先查重再新建。相同因果骨架优先合并证据；只有触发、冲突或兑现逻辑实质不同才新建卡。
5. 禁止复制参考书人物、专名、标志性表达或完整事件链。推荐时至少重设触发原因、冲突对象、主角目的、资源或场景、兑现方式中的三项。
6. 任何新建、修改、合并、移动、删除、索引重建或调用记录写入，都先说明准确路径、操作类型、影响范围与覆盖风险，并取得用户明确授权。

## 情绪优先原则

1. 检索前先形成“情绪任务单”：目标读者情绪、情绪来源、当前蓄压程度、本章兑现级别、可见兑现证据、兑现后的关系或局势余震。
2. 用户已明确情绪时直接采用；上下文只有一个高概率答案时说明判断并继续；若爽、虐、燃、甜等方向会实质改变方案，则先用一个简短问题确认。受项目规则限制不能提问时，选择最推荐方向并标记假设，同时保留明显不同的备选。
3. “击杀、升级、获奖、拿资源”是事件结果，不自动等于情绪兑现。至少要出现一种可观察证据：对手反应、旁观者认知变化、关系动作、公开结果、代价回响或主角内在选择被验证。
4. 通用素材库只保存可迁移机制；本书专属的伏笔、承诺、情绪债和读者期待应进入项目状态账本。调用记录只负责记录采用与冷却，不能替代状态账本。
5. 如果当前存在临近失效的活跃期待，优先检索其阶段兑现方式；除非用户明确要继续蓄压，不用新事件覆盖旧承诺。

## 低 token 检索纪律

素材库存在 `00_索引/检索索引.jsonl` 时，先运行脚本搜索，不要先读取整个 `总索引.md`、`标签索引.md` 或全卡目录。

默认流程：

1. 从当前故事状态形成情绪任务单，再提取“情绪词＋兑现证据词＋事件功能词”共2—4组检索词、必要模块与排除词。
2. 运行 `scripts/material_library.py search`，最多返回12条紧凑候选。
3. 根据因果适配、目标情绪匹配、人物边界、活跃期待、阶段任务与近期冷却筛到2—4张。
4. 只读取这2—4张原始卡。只有边界不清或需要核验来源时才下钻拆书摘要；默认不读源文。
5. 输出情绪任务单、实际命中、选用/弃用理由、原创映射、可见兑现、相似性规避与冷却结论。

旧卡缺少情绪字段时仍可依靠正文中的爽点、冲突和风险兼容召回，但必须人工复核，不能把空字段当成“没有情绪价值”。项目自带脚本若尚未支持新版情绪字段，先把情绪词写入 `--query` 并人工筛选，不得因此跳过情绪任务单。

如果紧凑索引缺失或过期，脚本可以即时从卡片构建内存候选并警告；未经写入授权不得自动落盘更新索引。

## 工具入口

~~~powershell
python scripts/material_library.py audit --library "<共享素材库绝对路径>"
python scripts/material_library.py build --library "<共享素材库绝对路径>"
python scripts/material_library.py search --library "<共享素材库绝对路径>" --query "紧张 智斗爽 团队认可 环境反杀" --modules "战斗,人物关系,钩子" --exclude "越阶突破,高层关注" --limit 12
~~~

`audit` 和 `search` 是只读操作；`build` 会覆盖机器索引，必须先取得授权。项目若提供自己的 `素材库/tools/material_library.py`，优先使用项目脚本入口。

## 完成标准

- 新增素材：原卡、紧凑索引、来源计数和人工可读索引相互一致，并报告新建/合并/待确认结论。
- 检索方案：不得先凭印象写方案再反向匹配卡片；必须先给出情绪任务单，再给出真实卡ID、可见兑现设计和弃用理由。
- 审计重构：区分确定性结构问题与需要人工判断的语义问题，不用脚本擅自合并或删除素材。
