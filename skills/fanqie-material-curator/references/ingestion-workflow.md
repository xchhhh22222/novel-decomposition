# 素材新增、合并与迁移流程

仅在用户要求添加、整理、去重或迁移素材时读取本文件。

## 一、确定输入层级

先判断用户提供的是原始小说文本或章节、单书章节拆解、单书结构总结、跨书聚类，还是既有套路卡修订意见。高层摘要不能冒充原文章节证据；模型记忆不能写成来源。

## 二、提取候选机制

对每个候选只保留以下骨架：

`触发条件 → 主角目标 → 主动动作 → 阻力升级 → 代价 → 可见兑现 → 后续影响`

同时提取情绪骨架：

`读者期待来源 → 蓄压/加压 → 转机 → 可见兑现证据 → 情绪余震`

两条链至少各自成立且能互相解释，才能进入正式套路卡。只有事件、没有可见情绪兑现的内容先保留为拆书观察；只有“很爽”“很燃”等感受、没有事件因果的内容也不入卡。把“作者希望读者产生什么情绪”与“角色在故事里想做什么”分开；不得把作者功能写成主角动机。

## 三、查重

1. 运行紧凑索引搜索，以目标情绪词、机制词、触发词、兑现证据词各检索一次。
2. 读取最相近的2—4张原卡。
3. 比较触发、目标、阻力、解法、情绪曲线、兑现证据、后果七项。

结论只能是：

- `MERGE`：核心因果相同，补来源或变体；
- `NEW`：至少两项核心逻辑实质不同，或情绪曲线与兑现证据形成可独立复用的新机制；
- `SPLIT`：旧卡混合多个独立机制；
- `HOLD`：证据不足或边界不清，进入待确认区。

相同题材、场景或名词不等于同一机制；仅换地图和人物也不构成新机制。

## 四、商业可用性审核

正式入库前确认：

- 主角有可见目标与选择，不只是旁观或被赠予；
- 冲突能升级，且不是靠配角集体降智；
- 有具体兑现类型与兑现周期；
- 目标情绪有前置依据，且能指出读者看得见的兑现证据；
- 兑现之后存在关系、认知、身份、资源、目标或风险余震，而非场景结束即归零；
- 能说明适用阶段和禁用条件；
- 能与至少一种辅助机制或钩子衔接；
- 改编时可以脱离原作专名与完整事件链。

商业可用性不足不等于删除：可以标为 `candidate`，等待更多来源或重新拆分。

## 五、写入授权与操作

在写入前展示目标文件、`NEW/MERGE/SPLIT/HOLD` 结论、拟写字段、来源依据、索引更新范围。取得用户明确同意后才执行。

写入顺序：

1. 新建或修改原始卡；
2. 运行 `audit`；
3. 运行 `build` 重建机器索引；
4. 复核人类索引中的数量和路径；
5. 重新读取变更卡与检索结果；
6. 报告验证结论。

不得用自动脚本执行语义合并、拆卡或删除。脚本只负责确定性字段解析、索引生成和问题提示。

## 六、旧库迁移顺序

不要一次性重写整个旧库。按收益排序：

1. 高频使用且正文过长的卡；
2. 跨域近重复卡；
3. 一卡混合多机制的卡；
4. 只有事件收益、缺情绪前提或可见兑现证据的卡；
5. 缺使用前提、禁用条件或兑现周期的卡；
6. 低频且仅单书支持的候选卡。

旧卡未迁移前，由索引脚本从现有标题、标签与正文小节生成兼容记录；不得因此把推导字段回写成已确认事实。
