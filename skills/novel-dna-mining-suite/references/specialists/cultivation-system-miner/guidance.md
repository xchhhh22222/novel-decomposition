# 修炼体系横向拆解器

## 模式路由

- 单书抽取：先读取 [schema.md](references/schema.md)。
- 横向近邻、聚类与 QA：再读取 [clustering-and-qa.md](references/clustering-and-qa.md)。
- 结构校验：运行 `python scripts/validate_outputs.py <jsonl或目录> --kind <per_book|nearest_neighbor|cluster|qa|handoff|gap>`；跨书必须额外提供 `--expected-books`、`--all-books-complete` 和 `--completion-manifest <per_book/gap.jsonl>`。

## 单一职责

本 Skill 只回答：

> 成长系统如何运行，主角当前到底处于什么成长状态，以及名义等级与真实能力之间为什么会出现差异？

修炼体系不是一张简单的战力表。必须把以下八个层次分开记录、分开取证、分开比较：

1. **通用修炼体系**：这个世界所有或大多数修炼者遵循的公共规则、训练路径和成长权限；
2. **境界体系**：等级、阶段、突破条件、阶段差异和正式境界变化；
3. **主角构筑**：主角实际选择的属性、路线、技能组合、构筑方向和取舍；
4. **金手指接口**：外挂如何影响成长、提供选择或改变效率，但不重新拆解金手指输入/处理/输出；
5. **实际战力**：人物当前真正能打到什么程度，以及与名义境界不一致的可证据化原因；
6. **技能熟练度**：技能的获得、学习、掌握、精通、演化和熟练程度；
7. **装备与资源**：武器、丹药、材料、功法、积分、消耗品及其对成长的短期或长期影响；
8. **身份与权限**：军衔、学生资格、组织权限、秘境准入、职业资格等外部通行条件。

本 Skill 不负责：

- 金手指的输入、处理、输出、成长母型和情绪母型；
- 世界观中的社会资源分配、制度史、组织母型和地图母型；
- 人物功能、人物卡、关系卡或人物长期弧线；
- 主线、支线、升级动机、线路生命周期或阶段交汇；
- 开篇窗口、分卷结构、篇章节奏或剧情机制卡；
- 可直接入库的正式素材卡。

相关内容只能作为接口、依赖、证据或边界说明出现，不能替代对应专项。

## 八层边界与硬区分

### 通用体系与境界体系

通用修炼体系回答“多数修炼者如何训练、获得能力、消耗资源并进入下一阶段”；境界体系回答“正式等级如何命名、如何突破、每阶段有什么稳定差异”。世界观提供的制度与资源环境不等于修炼规则本身。

### 境界与实际战力

名义境界只是一个维度，实际战力还可能受主角构筑、技能熟练度、装备、资源状态、经验、环境、克制、信息差、规则优势和可见代价影响。

因此：

- 境界高不等于实际战力一定高；
- 越级战斗不自动证明正式境界突破；
- 击杀强敌不自动证明境界变化；
- 短时爆发、规则克制、战术成功和环境优势必须与正式境界分开记录。

### 技能获得与技能掌握

“获得技能”“看到技能”“解锁技能”“拥有功法”只说明输入或权限发生变化，不等于人物已经掌握。掌握、精通、演化和熟练度必须有训练、施展、结果、稳定性、失败修正或他人反应等证据。

因此：

- 获得技能不等于已掌握技能；
- 技能熟练度提升不等于境界突破；
- 技能效果增强不自动等于通用修炼体系升级；
- 一次成功施展不自动等于长期稳定掌握。

### 资源、装备与永久成长

武器、丹药、材料、功法、积分和临时资源必须区分来源、消耗、持续时间、归属和是否改变自身基础状态。

因此：

- 资源到账不等于永久战力增长；
- 获得装备不等于境界提升；
- 装备加成、药效、阵地或外部辅助必须与自身成长分离；
- 资源只有在被实际吸收、训练、转化或验证时，才可能成为修炼成长证据。

### 身份、权限与修炼等级

军衔、学生资格、组织权限、秘境准入和职业资格改变的是行动许可、资源访问或信息范围，不自动改变修炼等级、技能熟练度或基础战力。

权限变化只有在原文明确显示它改变了修炼路径、突破条件或正式成长状态时，才能作为修炼系统接口记录；否则保留在身份/权限层。

### 金手指接口

只记录金手指如何影响修炼成长，例如提供何种资源入口、选择权、学习效率、验证场、限制解除或风险代价；不重复拆解其输入、处理、输出、限制和成长母型。金手指规则与公共修炼规则冲突时，保留接口关系和证据，不把外挂行为伪装成世界通用规则。

## 与相邻专项的分工

- `novel-worldbuilding-miner`：负责社会如何产生、分配和限制修炼资源、权限与制度；本 Skill 只记录这些内容如何进入修炼成长、突破条件、训练机会或实际战力。
- `novel-golden-finger-miner`：负责外挂的输入、处理、输出、成长和情绪兑现；本 Skill 只记录外挂对成长状态的接口影响。
- `novel-character-function-miner`：负责人物承担的功能、关系和人物弧线；本 Skill 只记录人物的成长状态，不输出人物卡。
- `novel-plotline-miner`：负责“为什么必须升级”、主线压力和线路推进；本 Skill 只记录升级系统本身如何运行，不替主线补动机。
- `novel-opening-miner`：负责开篇窗口与首次承诺；本 Skill 可提供首次修炼/境界证据，但不输出开篇母型。
- `novel-arc-structure-miner`：负责分卷、阶段和篇章结构；本 Skill 可提供成长阶段边界，但不输出篇章结构。
- `novel-plot-mechanism-miner`：负责具体剧情机制；本 Skill 可提供成长规则作为证据，不把一次事件链抽成剧情机制卡。

## 证据优先级与不确定性

证据优先级为：

1. 已通过 QA 的章节事实；
2. 已存在且可核验的逐章读者情绪覆盖；
3. 阶段、篇章或线路资料；
4. BOOK DNA 与书内聚类，仅作导航；
5. 原文回查，仅用于境界首次展示/突破、技能掌握、资源转化、战力验证或章节归属不清的核验。

书名、简介、题材标签、宣传语和模型记忆不能独立支撑修炼体系结论。正式境界变化必须有直接证据，例如明确境界名称/阶段变化、突破条件完成及结果、修炼体系承认的状态变化或可核验的系统记录。

“突破”“变强”“击杀强敌”“获得称号”“拿到资源”“进入组织”这些词本身都不是充分证据。必须区分：

- 正式境界变化；
- 短时 buff；
- 装备或药物加成；
- 技巧克制；
- 环境与规则优势；
- 越级战斗；
- 技能熟练度变化；
- 身份或权限变化。

证据不足时使用 `UNKNOWN`、`partial`、`HOLD` 或派生 `gap`，不得按网文常识补全境界、突破条件、阶段差异、技能掌握或成长结果。

## 运行流程

1. **冻结范围**：登记批次、目标书、章节范围、允许来源、情绪覆盖、已知缺口和禁止输出；
2. **提取公共体系**：记录多数修炼者共享的规则、训练路径、资源门槛和公共权限；
3. **提取境界变化证据**：区分正式境界展示、突破条件、阶段差异和直接变化证据；
4. **分离成长层次**：分别记录主角构筑、实际战力、技能熟练度、装备/资源和身份/权限；
5. **标记接口**：记录金手指、世界观和主线对修炼成长的接口，不越界重拆；
6. **单书 QA**：检查层次混淆、境界证据、技能掌握、资源转化、战力差异和未知项；
7. **跨书比较**：全部目标书完成单书抽取与 QA 后，比较成长系统如何运行，不比较表面等级名词；
8. **人工交接**：输出 candidate、证据引用、差异边界和待确认决策，不自动入库。

支持多书批量处理时，书籍分片必须互不重叠；分片先独立输出，再由专项总结合并。同一本书的单书结果完成前，不建立横向近邻或聚类。某本书证据不足时只标记该书缺口或低置信，不用其它书的体系补齐。

## 横向比较原则

跨书比较必须比较“成长系统如何运行”，至少区分：

- 公共修炼规则如何约束成长；
- 境界如何定义阶段、突破和权限；
- 主角构筑如何选择路线并承担取舍；
- 实际战力如何由境界以外的因素修正；
- 技能熟练度如何获得、验证和演化；
- 装备/资源如何进入成长，是否可替代或不可替代；
- 身份/权限如何打开成长路径但不冒充等级；
- 金手指、世界观和主线如何作为接口影响成长。

“都有一境二境”“都有炼体炼气”“都有技能升级”“都有突破”不能单独支撑近邻或聚类。每个候选都要说明相似运行环节、决定性差异、证据范围和是否应保持独立；证据不足时使用 `insufficient_evidence` 或 `HOLD`，不强行归类。

## 状态与写入边界

默认输出位置（仅在用户授权后落盘）：

```text
素材库/DNA素材/04_修炼体系/per_book/
素材库/DNA素材/04_修炼体系/candidate/
素材库/DNA素材/04_修炼体系/qa/
```


- 本 Skill 只输出 `candidate`；
- `UNKNOWN`、`partial`、`HOLD` 和 `gap` 必须显式隔离，并说明对下游判断的阻断；
- 单书候选不能直接称为高频成熟母型；
- 全部目标书单书 QA 完成后，才能建立正常跨书近邻与聚类；
- 不修改章节事实、逐章情绪记录、金手指正式产物、世界观正式产物、总索引或正式素材库；
- 任何需要改变 schema、升级状态、合并正式卡或重建索引的动作，交给上位总控和人工审核。

## 禁止事项

- 根据书名、简介、题材标签或一句卖点猜修炼体系；
- 把境界高低直接当作实际战力；
- 把获得技能直接当作掌握技能；
- 把熟练度提升、装备加成、资源到账、权限提升或击杀结果直接当作境界升级；
- 为了填满成长链而补造突破条件、阶段差异或技能掌握证据；
- 把金手指、世界观、人物、主线、开篇、篇章或剧情机制字段复制进本专项；
- 用专名、题材皮肤、等级名称或表面场景制造新的成长系统母型；
- 在全部目标书完成前建立正常跨书聚类；
- 把单书候选写成 `active`、`deprecated` 或正式素材卡；
- 修改源章节、正式素材库、总索引或既有 canonical 情绪 Schema。
