# 逐章读者情绪专项聚类与 QA

本文件规定如何检查章节情绪覆盖、承诺生命周期、节奏疲劳和跨书聚类。它只读取现有 canonical 章节情绪字段及派生记录，不修改 `chapter-emotion-schema.md`，不改写章节事实，也不把 QA 结果升级为正式素材卡。

## 1. 三层边界

QA 按以下顺序执行：

1. **单书完整性 QA**：确认请求范围内的章节覆盖、记录唯一性、Schema 合法性和证据可回溯；
2. **情绪与节奏 QA**：确认读者情绪、期待—兑现关系和单书节奏审计没有明显逻辑错误；
3. **跨书近邻与聚类 QA**：只有所有目标书完成单书抽取和 QA 后，才比较情绪运行方式并形成候选聚类。

上一层未通过时，不进入下一层的高置信聚合。任何层都只能产生 `candidate`、`HOLD`、`FAIL`、`gap` 或 `unclustered` 等可审计结果，不提供自动写入 `active` 或正式素材库的路径。

## 2. 单书完整性 QA

### 2.1 范围与覆盖

从输入包读取冻结的 `book_id`、`chapter_ranges`、排除章节和 `known_gaps`，建立期望章节集合。将 canonical `chapter_emotion.jsonl` 中的 `chapter` 或稳定 `chapter_ref` 映射到该集合。

- 请求范围内没有记录且不在已知缺口中的章节：列入 `missing_chapters`，结果至少为 `HOLD`；
- 已知缺口：写入派生 `gap`/QA 记录，注明缺口范围、来源和阻断的下游判断；
- 章节只出现在排除范围：不能计入覆盖率，也不能静默当作缺章；
- 目标书没有任何可核验章节证据：生成 `record_type: gap`，不得伪造 `per_book` 完整包；
- 覆盖率分母使用冻结的目标章节数，分子只计算 `qa_status: PASS` 的 canonical 记录；HOLD/FAIL 记录可以保留，但不计入可用覆盖。

### 2.2 缺章与重复章

按以下三个键分别检查：

- `(book_id, chapter)`；
- `chapter_ref`；
- `record_id`。

同一键出现多次，或不同键指向无法解释的同一章节，列入 `duplicate_chapters`。来源文件或分批拆解导致的重复只有在明确记录合并依据、来源指纹和保留规则后才能解除告警；不能简单取第一条。

章节号与物理文件编号不一致时，以 `chapter_ref` 为稳定锚点，把文件位置和偏移放进现有的来源说明字段或派生 QA 记录，不改写展示章号。

### 2.3 Canonical Schema 与证据

验证器必须以 `../../core/chapter-emotion-schema.md` 为唯一字段和枚举来源，检查：

- 每行是否为一个完整 JSON 对象；
- `schema_version`、唯一键、章节引用和既有受控枚举是否合法；
- 主情绪是否唯一，辅情绪是否超过既有上限；
- `pressure_level` 是否在既有范围内；
- `payoff_level`、章节作用和来源指纹是否遵守既有规则；
- 章节位置能否由 `chapter_ref` 或 `evidence_path` 回溯；
- 指纹不能以猜测值冒充真实哈希；无法生成时必须保留 `UNAVAILABLE` 并在 QA 解释。

canonical 记录不因本文件而追加统一派生 envelope。派生 QA、gap、承诺、近邻和聚类记录必须另行使用 `schema.md` 规定的统一 envelope。

### 2.4 单书结果

- `PASS`：目标范围已解释，canonical 记录有效且证据可回溯，没有阻断性重复或缺章；
- `HOLD`：存在已声明缺口、UNKNOWN、证据不足、编号偏移或可人工解决的重复；记录保留但不支持高置信聚合；
- `FAIL`：Schema 不合法、记录互相冲突、范围无法判断或来源无法回溯；下游不得把该书当作可用覆盖。

每条派生 QA 记录必须说明范围、检查项、结果、`evidence_refs`、`unknowns` 和阻断原因。

## 3. 情绪与节奏 QA

所有检查均从 canonical 逐章字段派生，不能为了检测方便增加情绪字段。

### 3.1 读者情绪边界

检查 `main_reader_emotion`、`secondary_reader_emotions`、情绪对象和兑现证据是否描述读者被引导经历的东西，而不是只描述角色状态。

- 只有角色“愤怒、紧张、悲伤”而没有读者期待、担心、愤怒、心疼或爽感证据：标记情绪证据不足；
- 章节只有事件摘要，没有可定位的情绪对象、期待来源或章末余味：至少 `HOLD`；
- 不因“主角赢了”自动填成长爽、打脸爽或收获爽。

### 3.2 期待与兑现

对 `promise_opened` 和 `promise_paid` 建立跨章节承诺表。相同承诺必须沿用稳定、可识别的短语；同义改写只有在证据明确指向同一承诺时才允许合并。

逐项执行：

1. `promise_paid` 必须能找到本章或前置章节的同名 `promise_opened`；找不到则标 `HOLD`，不能凭结果倒推承诺；
2. 开启承诺如果后续仍未兑现，保持开放并记录当前最后章节，不能自动关闭；
3. 强兑现必须存在前置期待、明确转折或选择、可观察兑现证据以及状态或情绪余震；
4. 升级、击杀、资源到账、获奖或排名变化本身只算事件结果，除非 canonical 字段和章节证据显示它验证了读者期待；
5. 承诺在超过一个十章窗口或自然阶段仍无解释时标记 `PROMISE_OVERDUE` 风险，但不擅自判定原书失败；
6. 证据指向多个可能承诺时标记 `UNKNOWN`/`HOLD`，交给人工确认。

### 3.3 每十章或自然阶段审计

将章节按连续十章窗口和自然阶段各运行一次。窗口边界、使用的章节记录 ID 和缺口必须写入审计。

使用以下可重复的风险规则：

- **连续同类情绪**：任意连续五章的主情绪相同，且压力来源、兑现方式或章末余味也高度相似，标记 `REPETITION_RISK`；只有情绪词相同但运行方式明显不同，不单独判定重复；
- **蓄压不兑现**：任意连续五章处于“继续蓄压”而没有局部/阶段兑现，或已开启承诺跨越一个十章窗口未出现合理回收，标记 `PRESSURE_DEBT`；
- **连续强兑现**：任意连续三章为本章强兑现，或五章窗口中至少三章强兑现，标记 `PAYOFF_SATURATION`；这是疲劳风险，不是对原作质量的事实判决；
- **兑现余震缺失**：强兑现后的一至两章没有可定位的余震、关系动作、身份/资源/认知/目标变化或新增风险证据，标记 `AFTERMATH_GAP`；
- **同形钩子**：任意连续三章 `hook_type` 相同，且钩子指向同类目标、风险或信息缺口，标记 `HOOK_REPETITION`；单纯同名但功能不同须写出差异；
- **多项同时命中**：同一窗口命中两项以上时，提高审计优先级，但不修改任何章节记录。

这些阈值是节奏审计的提示规则，不是跨书比较的绝对尺度。审计结果必须保留命中的章节范围、原始字段引用和“不足以判定”的说明。

## 4. 跨书 nearest-neighbor QA

### 4.1 启动门槛

只有当本批所有目标书都完成逐章抽取和单书 QA 后，才允许生成正常的 `nearest_neighbors`。若缺书、缺章节或 QA 未完成：

- 不得按书名、简介或 BOOK DNA 补造缺失书；
- 可以生成说明阻断原因的 QA/handoff 记录；
- 只能把无法比较的对象放进 `unclustered` 或 `insufficient_evidence`，不能伪装成近邻；
- QA 为 HOLD/FAIL 的书不能支撑高置信近邻或聚类结论。

### 4.2 比较维度

近邻比较的是情绪运行方式，不是题材名词或表面事件。默认使用七维 2/1/0 提示分：

1. 期待来源：目标、风险、信息缺口或承诺类型；
2. 压力推进：蓄压、加压、倒计时、资源缺口或认知落差的主要方式；
3. 主角选择与转折：是否由主动决策改变压力结构；
4. 兑现动作：验证、反制、公开结果、关系动作或其它实际落点；
5. 可见证据与余震：旁观者反应、关系、身份、资源、目标、风险或认知变化；
6. 承诺生命周期：开启、延迟、回收和回收后的新承诺如何衔接；
7. 章末推进：目标、风险、信息缺口和钩子如何把读者带入下一章。

每维按 `2=运行方式相同`、`1=部分相同`、`0=核心方式不同`，总分只作聚类提示：

- 11—14：优先判断同一情绪运行母型候选；
- 7—10：同一大类、不同子型的可能性较高；
- 0—6：通常保持不同母型或 `KEEP_SEPARATE`。

总分不能覆盖决定性差异。若期待来源、核心压力发动机、兑现证据或承诺生命周期实质不同，即使总分较高，也只能保持并列近邻并写明 `critical_override`。

每条近邻记录必须带：比较对象 ID、七维分数、证据引用、相似处、差异边界和 `merge_candidate`/`keep_distinct`/`insufficient_evidence` 决策。不能只写“很像”。

## 5. 跨书 clustering QA

### 5.1 聚类前检查

聚类前确认：

- 每个成员都有可回溯的单书或阶段证据；
- 成员的单书 QA 至少为 PASS，或明确隔离为 HOLD/不支持高置信；
- 所有目标书的完成状态已记录；
- 近邻记录先于聚类记录生成；
- 没有使用书名、专名、题材标签或一句话卖点作为主要相似度依据。

### 5.2 聚类层级与允许结果

采用：`大类 → 母型 → 子型/变体`。

- 大类：共同的情绪价值来源，例如危机承压、信息反制、公开验证、关系认可或资源兑现；
- 母型：稳定的期待—压力—选择—兑现—余震运行公式；
- 子型：输入、压力、选择、证据、承诺窗口或余震中的至少一项稳定不同；
- 变体：主要只改变题材皮肤、对象、资源或场景，核心运行方式不变；
- `unclustered`：当前没有合理近邻；
- `insufficient_evidence`：存在相似直觉，但证据不足以合并；
- `KEEP_SEPARATE`：同属大类但核心压力或兑现规则不同；
- `SPLIT`：已有候选把两种独立运行机制混在一起。

聚类不是强制分组。单书只默认保留为 `candidate` 变体或待观察母型；两本独立书可以支持母型候选，但仍需查重和人工审核。任何数量的来源书都不能自动生成 `active`。

### 5.3 聚类记录检查

每条 `cluster` 必须具备统一 envelope，并能定位：成员记录、近邻记录、共享运行方式、差异边界、支撑书数、证据引用、未知项和聚类决策。至少检查：

- 共享的是运行链，而不是“考试、比赛、秘境、击杀”等表面词；
- 每个成员的主情绪与兑现证据没有被平均化成无证据的概括；
- `unclustered`/`insufficient_evidence` 被允许并保留；
- 关键 UNKNOWN 不得进入 HIGH 置信结论；
- cluster 的 `status` 永远为 `candidate`；
- 不写正式素材卡、不更新正式素材库、不自动更改总索引。

## 6. 记录状态与失败处理

### 6.1 `HOLD` 与 `FAIL`

- `HOLD`：证据有缺口但仍可保留记录，等待补证或人工决策；
- `FAIL`：Schema、来源、唯一性或关键事实冲突，不能用于下游聚合；
- `gap`：目标书或章节没有足够证据，必须说明已知证据和被阻断输出；
- `unclustered`：证据充分但没有合理近邻；
- `insufficient_evidence`：可能存在近邻，但不足以作合并判断。

失败记录不删除、不用其它书补齐，也不通过降低描述精度来伪装通过。修复后只重跑受影响的书或窗口，不重写已通过的无关记录。

### 6.2 高置信限制

只有核心证据可回溯、没有关键 UNKNOWN、单书 QA 通过且近邻比较完整时，才可在派生记录中使用 `HIGH`。`HIGH` 也只表示证据置信度，不代表商业价值、成熟度或正式入库资格。

## 7. 禁止事项

- 通过给 canonical 逐章记录增加字段来解决 QA 问题；
- 根据书名、简介、题材或模型记忆补造章节、情绪、承诺或跨书样本；
- 把角色心情当作读者情绪；
- 把升级、击杀、奖励或资源自动判为兑现；
- 把情绪词相同直接当作同一母型；
- 在全部目标书完成前建立正常跨书聚类；
- 为了凑齐目标书、来源数或簇成员而强制合并；
- 把单书候选、近邻或 cluster 写成 `active`；
- 修改原章节事实、正式素材卡、总索引或其它专项产物。

## 8. QA 交付

机器可读 QA 使用 `../../core/chapter-emotion-schema.md` 的统一 envelope；人读审计可写入 `<output_root>/<BOOK_ID>/rhythm_audit.md`。每份交付至少包含：

- 目标书和章节范围；
- 检查项与结果；
- 命中的章节窗口或记录 ID；
- `evidence_refs`、`unknowns` 和阻断原因；
- 是否计入覆盖率、近邻或聚类；
- 仍需人工确认的决策点。

本文件只冻结判断和 QA 规则；具体 JSONL 结构由 `schema.md` 负责，具体字段合法性由验证脚本负责。
