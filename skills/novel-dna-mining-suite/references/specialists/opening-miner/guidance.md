# 小说开篇横向拆解器

## 模式路由

- 单书抽取：先读取 [schema.md](references/schema.md)。
- 横向近邻、聚类与 QA：再读取 [clustering-and-qa.md](references/clustering-and-qa.md)。
- 结构校验：运行 `python scripts/validate_outputs.py <jsonl或目录> --kind <per_book|nearest_neighbor|cluster|qa|handoff|gap>`；跨书必须额外提供 `--expected-books`、`--all-books-complete` 和 `--completion-manifest <per_book/gap.jsonl>`。

## 单一职责

本 Skill 不把前几章压缩成剧情摘要，而只回答：

> 一本小说在前 3、5、10、20 章内，如何让读者进入故事、理解核心前提、认识并相信主角、看到作品卖点被实际验证、接受持续冲突与未来承诺，并获得继续阅读的理由？

开篇分析的对象是多个观察窗口之间的运行变化，不是把第 1—20 章逐章罗列。必须说明开篇如何从“读者愿意进入”推进到“读者相信这本书值得继续读”，以及其中的停滞、重复、延迟、失速或有效回收。

本 Skill 不负责：

- 前 3、5、10、20 章的事件摘要、章节流水账或压缩版梗概；
- 一条具体剧情线的完整生命周期；
- 逐章 reader emotion 的重新标注、情绪词统计或角色心情分析；
- 人物百科、人物功能组合和关系发动机；
- 金手指的完整输入、处理、输出、限制和成长机制；
- 世界规则、制度、资源循环和地图因果；
- 境界、技能、战力、装备和成长体系；
- 全书分卷、阶段、地图、结构节奏或宏观篇章；
- 可复用剧情机制、套路母型或独立事件链；
- 可直接入库的正式开篇卡、正式素材卡或总索引。

相邻专项的信息只能作为接口或证据引用，不能替代相应专项完成业务对象。

## 核心观察窗口

以下窗口是运行时的观察范围，不是本轮要提前冻结的 schema 字段，也不是四份互相独立的章节摘要：

- **前 3 章**：检查读者是否完成进入、获得最低限度的主角与核心前提理解，并出现继续读的初始理由；
- **前 5 章**：检查核心题材、主角差异或核心卖点是否开始被实际证明，而不是仍停留在说明和准备；
- **前 10 章**：检查持续冲突、未来承诺、风险升级和第一次有效回收是否已经形成可追踪的运行链；
- **前 20 章**：检查是否形成稳定的 continuation driver，以及是否出现重复解释、迟迟不启动、连续准备无验证、卖点失速或承诺悬置过久。

如果目标范围不足以覆盖某个窗口，必须保留缺口或降低结论置信度，不能用后文倒推缺失窗口，也不能用其它书补齐。

## 十二类开篇观察对象

### entry / 读者进入

记录读者通过什么场面、问题、异常、欲望、风险、承诺或信息缺口被拉进故事。entry 不是一句宣传语，也不是“第一章发生了某件事”；必须说明读者当时被要求关心什么，以及后续哪种期待使进入得以延续。

### protagonist_establishment / 主角建立

记录开篇如何通过主角的行为、主动选择、处境、能力限制、资源缺口、风险承受和他人反应，让读者形成对主角的可验证认识。人物被介绍成聪明、凄惨、强大、特殊或有天赋，不等于主角已经完成建立；必须看到主角如何行动并承担后果。

### premise_exposure / 核心前提暴露

记录读者何时、通过什么证据真正理解核心题材、世界条件、主要冲突或作品运行前提。世界观名词、背景说明和设定百科不自动等于 premise exposure；只记录读者获得了足以理解故事运行的内容，不重建完整世界规则。

### golden_finger_reveal / 金手指或核心外挂揭示

如果作品存在外挂、系统或其它核心能力差异，必须分开观察：

`首次出现 → 首次理解 → 首次验证 → 首次兑现/卖点证明`

“第几章拿到外挂”只能作为定位信息，不能替代四个阶段。首次出现可能只是异常露面，首次理解是主角或读者知道它怎样工作，首次验证是规则被行动证实，首次兑现/证明是它实际展示核心卖点并改变读者期待。没有证据时保留未知，不把一次展示强行写成完成验证。

没有传统金手指时，观察对象可替换为作品真正的核心卖点或差异能力，但不得为了填字段虚构外挂。

### conflict_activation / 持续冲突启动

记录真正推动故事持续前进的首个冲突、目标冲突、资源门槛、制度压力、身份风险、时间压力或关系矛盾何时形成。第一次打架、一次争吵或单场危险不自动等于 conflict activation；必须能看到它如何在后续继续制造目标、选择、阻力或代价。

### promise_setup / 承诺建立

记录开篇向读者建立的未来可兑现承诺，例如主角要证明什么、获得什么、解决什么、揭开什么、进入什么位置或承担什么风险。承诺必须能回到章节或阶段证据；不能把所有悬念都扩大成长期承诺。

### selling_point_proof / 核心卖点证明

记录作品最重要的卖点何时第一次被实际演示并得到可观察结果。口头说明、人物夸赞、设定介绍、主角宣称或宣传语不是 proof；必须有能力运转、选择被验证、规则产生结果、对手或旁观者认知改变、资源限制显现或其它可观察证明。

### stakes_escalation / 风险升级

记录开篇如何逐步提高风险、代价、资源稀缺、身份暴露、关系损失、行动窗口或时间压力。事件数量变多、敌人变强或场景变大不自动等于 stakes escalation；必须说明主角或读者承担的后果怎样发生变化。

### first_payoff / 第一次有效回收

记录开篇承诺、目标、问题或卖点第一次获得有效结果的窗口、证据和余震。爆点、高潮、胜利、升级、击杀、资源到账或反转不自动等于 first payoff；必须存在可回溯的前置期待，并且结果确实回收了它的一部分。

### continuation_driver / 持续阅读驱动

记录在章节末、阶段末或窗口转换处，什么真实问题、目标、风险、承诺、信息缺口、关系变化或状态变化使读者有理由继续阅读。章末留悬念、突然出现新敌人或机械截断不自动成为有效 driver；必须说明它与前面已建立的运行链有什么关系。

### information_pacing / 信息节奏

记录哪些信息在当前窗口必须让读者知道，哪些信息被合理延后，以及信息释放如何改变理解、期待、风险或选择。信息多不等于信息节奏好；堆设定、反复解释、过早泄底和无关谜语都要与实际阅读功能区分。

### opening_compression / 开篇压缩与拖延

记录开篇是否存在可删除的重复解释、同功能场景反复出现、连续准备却没有验证、主角长期被动、冲突迟迟不启动、卖点证明被推迟或承诺无法回收等问题。开篇事件多不等于节奏快，节奏快也不等于结构有效；判断必须落到窗口推进和读者期待变化。

## 开篇对象的硬边界

以下区别必须保持：

- 前 20 章剧情摘要 ≠ opening analysis；
- 第一章 hook ≠ 整个 opening；
- 爆点 ≠ payoff；
- 第一次打架 ≠ conflict activation；
- 世界观说明 ≠ premise exposure；
- 获得外挂 ≠ selling-point proof；
- 章节末悬念 ≠ 自动 continuation driver；
- 主角被介绍成聪明、很惨或很强 ≠ protagonist establishment；
- 读者知道一个设定 ≠ 主角已经完成相应 plotline；
- 事件数量多 ≠ 开篇节奏快；
- 信息数量多 ≠ information pacing 良好；
- 一次角色出场 ≠ 角色功能已经成立；
- 一次机制使用 ≠ 可复用剧情机制已经成立；
- 一次升级、击杀、胜利或资源到账 ≠ first payoff。

开篇可以引用 plotline、chapter emotion、character function、golden finger、worldbuilding、cultivation、arc structure 或 plot mechanism 的结果，但必须保留接口关系，不把相邻对象复制成开篇结论。

## 证据边界

证据优先级遵守上位总控契约：

1. 已通过 QA 的章节事实、行为、选择、冲突结果和状态变化；
2. 已存在且可核验的逐章 reader-emotion overlay，用于确认期待、蓄压、兑现和章末余味；
3. 已确认的剧情线、人物功能、金手指、世界观、修炼体系或阶段资料，用于定位接口和窗口变化；
4. BOOK DNA、章节索引和既有聚类，仅作导航与交叉核验；
5. 原文回查，仅在首次出现/理解/验证/兑现、承诺窗口、冲突启动、主角选择或章节归属不清时使用。

书名、简介、题材标签、宣传语、章节标题、人物名字和模型记忆不能独立支撑开篇结论。证据不足时保留 `UNKNOWN`、`partial`、`gap` 或 `HOLD`，不能用常见网文经验补造 opening 结构、卖点、承诺或回收。

每条开篇结论至少应能回答：

- 读者因何进入，以及进入后被要求期待什么；
- 主角通过什么可观察行动被建立；
- 核心前提何时被真正理解；
- 金手指或核心卖点在四个揭示/验证阶段分别发生了什么；
- 持续冲突由什么启动并如何延续；
- 哪些承诺被建立、延迟或首次回收；
- 风险、代价、资源、身份、关系或时间压力怎样逐步改变；
- 信息释放如何帮助或阻碍理解；
- 窗口末尾为什么值得继续读；
- 哪些重复、准备、解释或延迟正在损伤开篇压缩。

## 与相邻专项的分工

- `novel-plotline-miner`：负责具体剧情线的完整生命周期；本 Skill 只观察线路在前 3/5/10/20 章中的启动、暴露、早期推进和首次回收，不重新构建完整 line lifecycle。
- `novel-chapter-emotion-miner`：负责逐章 reader emotion、蓄压、兑现和余震；本 Skill 只引用其结果判断开篇情绪运行，不重新标注每章情绪。
- `novel-character-function-miner`：负责人物功能组合、关系发动机和功能变化；本 Skill 只观察关键人物何时通过什么开篇场面进入，并怎样改变主角选择、资源或风险。
- `novel-golden-finger-miner`：负责外挂的输入、处理、输出、限制和成长；本 Skill 只观察开篇的首次出现、理解、验证和卖点证明，不重做外挂机制。
- `novel-worldbuilding-miner`：负责规则、稀缺、制度、组织和冲突因果；本 Skill 只观察读者何时得到足以进入故事的世界理解，不重建世界观母型。
- `novel-cultivation-system-miner`：负责境界、技能、装备、战力和成长循环；本 Skill 只观察成长门槛、升级或战力展示何时服务开篇卖点，不重做成长系统。
- `novel-arc-structure-miner`：负责全书阶段、分卷、地图和宏观结构；本 Skill 只负责前期开局窗口，不替代全书 arc。
- `novel-plot-mechanism-miner`：负责可复用剧情机制和运行方式；本 Skill 只记录某机制在开篇第一次如何起效或被证明，不生成机制模板。

如果某个结论只有相邻专项才能确认，保留接口说明、证据引用和依赖缺口，不越界代替相邻专项下结论。

## 上位契约与输入

严格遵守：

- `../../../SKILL.md`；
- `../../core/horizontal-specialist-contract.md`；
- `../../core/integration-and-qa.md`。

输入必须来自 orchestrator 冻结的批次包，至少说明目标书、允许章节范围、来源、情绪 overlay 接口、已知缺口和禁止输出。不得自行扩大书单、章节范围、来源或窗口外的结论范围。

章节事实未通过 G1 时，不生成高置信开篇结论；情绪覆盖未通过 G2 时，只能保留相应缺口或低置信接口，不用模型印象替代。目标范围没有覆盖某个观察窗口时，必须显式说明未覆盖原因。

所有派生记录保持共享的 `candidate-only` 与 derived envelope 约束。具体记录字段、窗口表示、聚类结构、评分方式和验证脚本已在当前 references 与 scripts 中冻结，本 Skill 不创建第二套 canonical schema。

## 运行流程

执行时按以下过程执行：

1. **冻结输入**：登记批次、目标书、允许章节范围、实际可用窗口、来源 QA、情绪 overlay、已知缺口和禁止输出；
2. **划定观察窗口**：分别检查前 3、5、10、20 章能观察到的运行变化；窗口是观察边界，不是四份摘要或强制成功标准；
3. **识别 entry**：定位读者进入的场面、问题、异常、欲望、风险或承诺，并说明后续期待如何延续；
4. **建立主角**：从行为、选择、限制、处境、资源缺口、风险和他人反应确认 protagonist establishment；
5. **暴露核心前提**：判断读者何时获得足够的题材、世界、冲突和运行规则理解，区分说明与实际理解；
6. **追踪核心卖点**：若有外挂，分别记录首次出现、理解、验证和兑现/证明；同时确认作品核心卖点何时由实际结果而非口头说明支撑；
7. **确认冲突与承诺**：定位持续冲突的真正启动、未来 promise setup、stakes escalation 和相关人物/线路接口；
8. **核对早期兑现**：寻找 first payoff 的前置期待、可见结果与状态或读者期待余震，不能把爆点或事件结果自动算回收；
9. **判断 continuation driver**：说明每个窗口末端有什么真实目标、风险、信息缺口、承诺或状态变化促使继续阅读；
10. **检查信息节奏与压缩**：检查必要信息、延迟信息、重复解释、连续准备、冲突延迟、卖点失速和承诺悬置；
11. **单书 QA**：核对窗口覆盖、证据回溯、十二类对象的边界、相邻专项接口、UNKNOWN/gap/HOLD 和摘要越界；
12. **跨书比较**：全部目标书完成单书抽取和 QA 后，才比较开篇运行结构、卖点验证、承诺—回收链和 continuation driver，不按系统流、退婚流、考试开局或打怪开局等表面标签聚类；
13. **人工交接**：输出 candidate、证据引用、相近候选、差异边界、阻断项和待确认决策，不自动入库。

## 横向比较原则

跨书比较的对象是“开篇如何运转”，至少比较：

- entry 如何建立并转化为持续期待；
- protagonist establishment 通过什么行为、限制和后果完成；
- premise exposure 如何在信息释放与读者理解之间推进；
- golden-finger reveal 的四阶段是否分离，selling-point proof 如何出现；
- conflict activation 如何从局部事件变成持续推进；
- promise setup 如何进入 stakes escalation 并得到 first payoff；
- continuation driver 由什么状态、目标、风险或信息链支撑；
- information pacing 与 opening compression 如何影响窗口转换；
- 相邻线路、人物、情绪、机制和阶段接口如何共同服务开局。

“都是穿越开局”“都有系统”“第一章都打怪”“都有退婚”“都有学院考试”不能单独支撑近邻或聚类。必须比较开篇运行链、验证证据、承诺回收、信息节奏和窗口末端的差异。证据不足时使用 `insufficient_evidence` 或 `HOLD`，不强行归类。

## 交付、状态与写入边界

默认输出位置（仅在用户授权后落盘）：

```text
素材库/DNA素材/07_开篇/per_book/
素材库/DNA素材/07_开篇/candidate/
素材库/DNA素材/07_开篇/qa/
```


每个专项批次固定规划五类交付：

1. `per_book`：单书前 3/5/10/20 窗口的开篇观察、证据、卖点验证、承诺与继续阅读驱动；
2. `nearest_neighbors`：按开篇运行结构、验证方式、承诺—回收和信息节奏比较的近邻记录；
3. `clusters`：开篇运行方式及其变体的聚类候选；
4. `qa`：窗口覆盖、证据缺口、边界混淆、重复解释、拖延和待确认项；
5. `handoff`：交给人工审核的 candidate、证据引用、相近候选和决策点。

必须遵守：

- 所有专项结果只能是 `candidate`；不得生成或升级为 `active`、`deprecated` 或正式素材卡；
- `UNKNOWN`、`partial`、`gap`、`HOLD` 和 `FAIL` 必须显式保留，并说明对下游判断的影响；
- `nearest_neighbors` 与 `clusters` 必须等待全部目标书完成单书抽取和 QA，并通过 cross-book completion gate；
- 不写正式素材库、总索引、章节事实、情绪记录或其它正式资料；
- 不根据书名、简介、标签、宣传语或题材皮肤补造 opening 结构；
- 不修改相邻专项的 schema、索引、章节情绪记录或正式候选；
- 任何状态升级、schema 变更、跨专项合并或正式入库都交给上位总控和人工审核。

## 禁止事项

- 把前 20 章摘要改名为 opening analysis；
- 只分析第一章 hook 就宣称完成整个 opening；
- 因为爆点、高潮、升级、击杀、胜利或资源到账就自动标记 first payoff；
- 因为第一次打架、一次争吵或一次危险就自动标记 conflict activation；
- 因为世界观名词、背景百科或人物说明出现就自动标记 premise exposure；
- 因为主角获得外挂就合并首次出现、理解、验证和兑现；
- 因为章末留悬念、突然来敌人或机械截断就自动标记 continuation driver；
- 因为人物被形容为聪明、很惨、很强或特殊就自动完成 protagonist establishment；
- 因为事件多、信息多、敌人强或场景大就自动判断节奏快、信息节奏好或风险升级；
- 从书名、简介、标签、人物名字、章节标题、宣传语或模型记忆推断开篇结构；
- 用相邻专项的完整人物、线路、外挂、世界、修炼、篇章、情绪或机制对象填充开篇结论；
- 在所有目标书完成前建立跨书近邻或聚类；
- 把单书开篇候选写成 `active`、`deprecated` 或正式素材卡；
- 为了填满 3/5/10/20 窗口而补造承诺、卖点证明、冲突、回收或继续阅读理由。

## 交付前验收

每次交付前至少确认：

1. 前 3、5、10、20 章被作为观察窗口，而不是四份章节摘要或强制成功标准；
2. entry、protagonist_establishment、premise_exposure、golden_finger_reveal、conflict_activation、promise_setup、selling_point_proof、stakes_escalation、first_payoff、continuation_driver、information_pacing、opening_compression 十二类对象明确分离；
3. 金手指或核心卖点的首次出现、首次理解、首次验证、首次兑现/证明不会被合并；
4. hook、爆点、打斗、世界观说明、外挂获得、章末悬念、人物介绍、事件密度和信息数量不会自动替代对应开篇对象；
5. first payoff 有可回溯的前置承诺、目标或问题，并保留可观察结果；
6. continuation driver 来自真实目标、风险、信息缺口、承诺或状态变化，而不是机械断章；
7. opening 与 plotline、chapter-emotion、character-function、golden-finger、worldbuilding、cultivation、arc-structure 和 plot-mechanism 没有职责泄漏；
8. 五类交付、derived envelope、candidate-only、UNKNOWN/partial/gap/HOLD 和 cross-book completion gate 均由当前 schema、validator 与交付流程承接；
9. 跨书比较基于开篇运行结构、验证证据、承诺回收和信息节奏，不基于系统流、退婚、考试、打怪等表面标签；
10. 本文件不提前定义完整 schema 字段、窗口评分、opening grade 或正式聚类评分；
11. 没有写入正式素材库、总索引或其它正式资料的路径。
