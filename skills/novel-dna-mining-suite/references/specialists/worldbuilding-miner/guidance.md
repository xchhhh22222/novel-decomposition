# 世界观横向拆解器

## 模式路由

- 单书抽取：先读取 [schema.md](references/schema.md)。
- 横向近邻、聚类与 QA：再读取 [clustering-and-qa.md](references/clustering-and-qa.md)。
- 结构校验：运行 `python scripts/validate_outputs.py <jsonl或目录> --kind <per_book|nearest_neighbor|cluster|qa|handoff|gap>`；跨书必须额外提供 `--expected-books`、`--all-books-complete` 和 `--completion-manifest <per_book/gap.jsonl>`。

## 单一职责

本 Skill 只研究世界观如何运转，不做世界百科摘抄。核心问题是：

`规则 → 稀缺 → 利益/制度 → 冲突 → 剧情入口 → 读者情绪`

一条有效的世界观候选，必须说明某项可证据化的世界规则如何影响后续链条中的至少一个环节，并能回到章节或阶段证据。世界背景、名词、城市、组织、种族、地图或历史设定仅因“存在”不能自动成为世界观机制。

本 Skill 不负责：

- 金手指输入、处理、输出和成长母型；
- 修炼等级、战力构筑和突破体系；
- 人物功能、人物卡或关系卡；
- 主线、支线、开篇、分卷和篇章结构；
- 可直接入库的剧情机制卡或正式素材卡。

与上述内容相关的信息只能作为世界观接口、冲突证据或依赖说明，不能替代对应专项。

## 上位契约

严格遵守：

- `../../../SKILL.md`；
- `../../core/horizontal-specialist-contract.md`；
- `../../core/integration-and-qa.md`。

输入只能来自总控冻结的批次包：

```yaml
batch_id:
specialty: novel-worldbuilding-miner
book_ids:
allowed_sources:
chapter_ranges:
emotion_overlay_paths:
output_root:
forbidden_outputs:
known_gaps:
```

本 Skill 不自行扩大书单、章节范围、来源或输出范围。所有派生记录使用统一 envelope，状态只能是 `candidate`；不得生成或升级为 `active`、`deprecated`，不得写入正式素材库、总索引或源章节。

每个专项批次必须规划五类交付：

1. `per_book`：单书世界规则与因果链证据包；
2. `nearest_neighbors`：按规则运行方式比较的近邻记录；
3. `clusters`：大类、母型、子型和变体候选；
4. `qa`：覆盖、证据缺口、争议和阻断项；
5. `handoff`：交给人工审核的候选与待决策项。

具体记录字段由后续专项 schema 冻结；本文件不复制或提前扩展统一 canonical 情绪 Schema。

## 证据边界

证据优先级为：

1. 已通过 QA 的章节事实；
2. 已存在且可核验的逐章读者情绪覆盖；
3. 阶段、篇章或线路资料；
4. BOOK DNA 与书内聚类，仅作导航；
5. 原文回查，仅用于关键规则、首次验证、资源分配或章节归属不清的核验。

书名、简介、题材标签、宣传语和模型记忆不能独立支撑世界观结论。关键结论至少需要一个章节或阶段证据；证据不足时保留 `UNKNOWN`、`partial`、`HOLD` 或派生 `gap`，不补造完整因果链。

读者情绪只能引用已有 `emotion_overlay_paths` 与其证据，不能由本 Skill 创建、修改或重定义 `chapter-emotion-schema.md` 的字段。

## 世界观分析边界

### 必须追问的因果关系

围绕以下问题抽取，不把答案写成脱离证据的设定说明：

- 世界核心异常或基础前提改变了普通人的什么日常状态；
- 超凡力量如何进入社会，并由谁控制、验证或限制；
- 哪条规则制造了稀缺，稀缺如何产生竞争或分配问题；
- 官方、学校、军方、家族、公司或其它机构承担什么制度功能；
- 阶层如何形成、维持或流动；
- 威胁为何能够持续产生，而不是只出现一次敌人；
- 地图如何逐级开放，开放由什么资源、权限或危机触发；
- 信息由谁掌握，信息差如何改变人物选择和冲突；
- 哪些规则限制主角、限制他人或改变代价；
- 世界如何给金手指提供资源、敌人、制度或验证场；
- 世界如何给修炼体系提供资源和验证，但不替修炼专项拆解成长公式；
- 规则何时第一次被展示、验证和扩大，世界观揭示是否过密或停滞；
- 这些变化如何产生可观察的读者期待、压力、验证、兑现或余震。

只有“某地存在某组织”“有某种族”“有某等级”而没有规则作用、资源分配、制度约束、冲突后果或剧情入口时，只能作为背景事实或待核验信息，不能直接升级为世界观母型候选。

### 与其它专项的分工

- `novel-golden-finger-miner`：本 Skill 只记录世界为金手指提供的资源、敌人、制度或知识接口，不拆金手指运行规则；
- `novel-cultivation-system-miner`：本 Skill 只说明世界如何提供资源、权限和验证场，不输出境界、技能、突破或战力体系；
- `novel-character-function-miner`：本 Skill 说明制度如何约束人物选择，不输出人物目标、功能或关系卡；
- `novel-plotline-miner`：本 Skill 说明规则如何打开剧情入口，不追踪完整线路生命周期；
- `novel-opening-miner`：本 Skill 可以记录世界规则首次被展示或验证，不负责开篇窗口母型；
- `novel-arc-structure-miner`：本 Skill 可以记录地图、制度或冲突层级如何变化，不负责分卷结构；
- `novel-plot-mechanism-miner`：本 Skill 可以提供规则与冲突的证据，不把具体事件链抽成剧情机制卡。

## 运行流程

按以下阶段执行：

1. **冻结范围**：登记批次、目标书、章节范围、允许来源、已知缺口和禁止输出；
2. **提取规则证据**：从章节事实中记录可复述、可验证、能影响行动或分配的世界规则；
3. **建立因果链**：逐条追踪规则如何制造稀缺、利益或制度、冲突和剧情入口；链条不完整时显式保留缺口；
4. **检查边界与不确定性**：区分世界规则、人物选择、金手指效果、修炼规则和事件结果；不把推测写成已确认事实；
5. **关联情绪 overlay**：引用读者情绪记录，说明规则验证、资源争夺、制度压迫、信息揭示或地图开放带来的读者体验；不新增情绪字段；
6. **单书 QA**：检查章节覆盖、证据回溯、规则与后果的对应、重复记录、缺口、UNKNOWN、HOLD/FAIL 和候选状态；
7. **跨书比较**：只有所有目标书完成单书抽取和 QA 后，才按规则运行方式建立 `nearest_neighbors` 和 `clusters`；
8. **人工交接**：输出 candidate、证据引用、相近候选、差异边界和待确认决策，不自动入库。

支持多书批量处理时，书籍分片必须互不重叠；分片先独立输出，再由专项总结合并。某本书证据不足时只标记该书缺口或低置信，不用其它书的规则补齐。

## 横向比较原则

比较的是世界规则的运行方式，而不是表面名词。至少区分：

- 核心冲突发动机；
- 稀缺资源如何产生、分配和回流；
- 权力组织与阶层流动方式；
- 威胁持续生成方式；
- 地图和权限的扩张方式；
- 信息揭示和认知反转方式；
- 主角进入世界核心的通道；
- 世界规则与金手指、修炼体系的咬合接口；
- 规则验证后形成的读者情绪与可见证据。

“都有学校、军部、秘境、异族或考试”不能单独支撑近邻或聚类。每个候选都要说明相似运行环节、决定性差异、证据范围和是否应保持独立；证据不足时使用 `insufficient_evidence` 或 `HOLD`，不强行归类。

## 状态与写入边界

默认输出位置（仅在用户授权后落盘）：

```text
素材库/DNA素材/03_世界观/per_book/
素材库/DNA素材/03_世界观/candidate/
素材库/DNA素材/03_世界观/qa/
```


- 本 Skill 只输出 `candidate`；
- `HOLD`、`FAIL`、`UNKNOWN` 和 `gap` 必须显式隔离，并说明对下游聚合的阻断；
- 单书结果默认是单书候选或待观察变体，不能直接称为高频母型；
- 跨书聚类必须等待所有目标书的同类专项包完成；
- 不修改章节事实、逐章情绪记录、金手指正式产物、总索引或正式素材库；
- 任何需要改变 schema、升级状态、合并正式卡或重建索引的动作，交给上位总控和人工审核。

## 禁止事项

- 根据书名、简介、题材标签或一句卖点猜世界观；
- 把背景名词、地图、组织、种族或历史摘抄直接当成机制；
- 把世界共有修炼规则、主角金手指或人物天赋误写成世界观专项候选；
- 为了填满规则→稀缺→制度→冲突→剧情入口链而补造证据；
- 把角色心情或没有证据的读者感受写成情绪结论；
- 复制其它专项的人物、金手指、修炼、线路、开篇、篇章或剧情机制母型；
- 用专名、题材皮肤或表面场景制造新的世界观母型；
- 在所有目标书完成前建立正常跨书聚类；
- 把单书候选写成 `active`、`deprecated` 或正式素材卡；
- 修改源章节、正式素材库、总索引或既有 canonical 情绪 Schema。

## 交付前验收

每次交付前至少确认：

1. 每本目标书都有 `per_book` 记录或明确的 `gap`；
2. 每条核心世界规则都能回到章节或阶段证据；
3. 规则链中缺失的环节被标记为 partial、UNKNOWN 或 HOLD，而不是被推测补齐；
4. 情绪结论来自已有 overlay 或明确证据，不重造章节情绪字段；
5. `nearest_neighbors` 与 `clusters` 等跨书结果等到全部目标书单书 QA 完成后才生成；
6. 输出包含五类交付，并保持统一派生 envelope 与 `candidate` 状态；
7. 没有越界输出其它专项正式卡或写入正式素材库；
8. 结构验证、证据回溯、争议边界和人工 handoff 均有后续可执行的验收位置。

本文件冻结职责、边界、输入输出和流程；具体 worldbuilding 记录字段、聚类 schema、QA 脚本和前向测试以当前 references 与 scripts 为准，不形成第二套 canonical 情绪 Schema。
