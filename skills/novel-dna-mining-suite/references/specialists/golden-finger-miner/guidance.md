# 金手指横向拆解器

## 单一任务

只研究目标书单中的金手指，回答：

`输入什么 → 经过什么规则处理 → 输出什么 → 受到什么限制 → 如何成长 → 需要世界提供什么 → 怎样制造读者情绪`

拆完金手指即停止。世界观、修炼体系、人物、主支线、开篇和剧情模块只允许作为接口或证据出现，不生成它们的母卡。

## 模式路由

- **单书规范化提取**：读取 [references/golden-finger-schema.md](references/golden-finger-schema.md)。
- **多书聚类、去重或母型判断**：再读取 [clustering-and-qa.md](references/clustering-and-qa.md)。
- **只检查候选文件结构**：运行 `scripts/validate_golden_finger_outputs.py <文件或目录> --expected-books <BOOK_01,BOOK_02,...>`。

## 证据优先级

1. 已通过QA的章节事实；
2. 逐章情绪覆盖层；
3. 阶段结构或线路文件；
4. BOOK DNA与书内聚类；
5. 原文，仅在关键规则、首次验证或章节归属不清时回查。

BOOK DNA是导航，不是免核验的最终证据。关键字段不能只引用一句话卖点。

现有项目的QA可能分散在 `chapter_qa_report.md` 与 `progress.md`：先看覆盖范围与修改时间，再按批次合并状态；两者冲突时列为待定，不静默选择。没有逐章情绪层时，可临时从章节拆解的“爽点、信息差、章末钩子、状态变化”提取 `provisional_emotion`，置信度最高为MEDIUM，并明确等待情绪覆盖层复核。

## 工作流

1. **冻结书单**：记录目标书籍ID、章节范围、允许读取路径和已知缺口。
2. **逐书提取**：为每本书生成一条 `per_book` 记录，不提前建立母型。
3. **补情绪接口**：从逐章情绪层提取首次承诺、首次验证、阶段升级、强兑现和疲劳风险；没有情绪层时标记缺口，不凭印象补写。
4. **建立最近邻**：比较输入、处理、输出、限制、成长、资源循环和核心情绪，先找相同，再找差异。
5. **聚类**：输出大类、母型、子型、变体。名称、题材皮肤和专有名词不参与核心相似度。
6. **审核**：运行结构校验，人工复核争议合并、单书候选和高置信记录。
7. **交接**：只生成 `candidate` 和 handoff，不直接写入正式套路卡或索引。

默认输出到 `素材库/DNA素材/02_金手指/per_book/`、`candidate/` 与 `qa/`。用户只要求对话报告或未授权写入时，在对话中展示同一schema的结果并运行人工字段核对，不创建文件。

## 多代理执行

- 用户要求并发时，可以把16本书分成互不重叠的批次抽取；所有工作代理必须使用同一schema。
- 每个工作代理只写自己的分片文件，不共同修改聚类文件。
- 专项总控等待全部分片完成后再做横向比较。
- 某本失败只重跑该书；不得因一书缺证据而用其他书的规则补齐。

## 核心判断

- 金手指母型由运行规则决定，不由名称决定。
- “看到能力后学会”与“击杀后提取”可以同属复制大类，但输入不同，应是不同子型。
- “数值翻倍”与“敌人修炼返还”即使都使数值上涨，处理规则、资源循环和冲突发动机不同，不应合并。
- 区分“系统规则本身升级”和“系统不变、历次产物累积变强”；只有输入、处理或权限发生变化，才算金手指规则成长。
- 世界依赖只回答该金手指需要什么资源、敌人、制度或知识才能持续运转。
- 读者情绪必须落到可见证据：选择被验证、规则被证实、对手认知改变、收益到账、代价兑现或新风险出现。

## 禁止事项

1. 只看书名判断金手指。
2. 把主角的普通功法、种族天赋或世界通用能力误记为独有金手指，除非原书明确把它作为核心差异发动机。
3. 只写“很强、无敌、升级快”，不写输入、处理、输出和限制。
4. 把第一次展示、第一次验证和第一次强兑现混成同一事件。
5. 因专名不同建立新母型，或因结果都为“变强”强行合并。
6. 没有来源时推断中后期成长。
7. 输出世界观、人物、主线或剧情正式卡。

## 完成标准

- 目标书单每本都有 `per_book` 记录或明确缺口。
- 每条核心规则至少有一个章节或阶段证据。
- 每本书都记录金手指的情绪承诺、首次验证、主要兑现和疲劳风险。
- 每个聚类都有最近邻比较、母型判断、变体边界和来源书数。
- 单书来源默认保留为 `candidate`，不得冒充高频成熟母型。
- 输出通过脚本结构校验，并能交给总控生成总索引。
