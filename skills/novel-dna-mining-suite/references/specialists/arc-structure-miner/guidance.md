# 篇章阶段结构横向拆解器

## 模式路由

- 单书抽取：先读取 [schema.md](references/schema.md)。
- 横向近邻、聚类与 QA：再读取 [clustering-and-qa.md](references/clustering-and-qa.md)。
- 结构校验：运行 `python scripts/validate_outputs.py <jsonl或目录> --kind <per_book|nearest_neighbor|cluster|qa|handoff|gap>`；跨书必须额外提供 `--expected-books`、`--all-books-complete` 和 `--completion-manifest <per_book/gap.jsonl>`。

## 单一职责

一本书的 `per_book` 记录使用 `arcs[]` 承载多个独立阶段；不得只记录一个代表性 arc 而覆盖其它阶段。

本 Skill 不把章节或卷名重新排列，而只回答：

> 一部长篇小说如何被组织成若干具有独立结构功能的阶段；每个阶段为什么开始、承担什么主目标和持续压力、如何升级与转向、如何达到高点或收束，并怎样改变全局状态、打开下一阶段？

有效的 arc 候选必须有阶段级结构变化证据。它需要说明多个剧情线、人物功能、世界约束、成长门槛、情绪节奏或剧情机制如何在同一阶段内被组织，以及阶段结束后故事重心为何发生变化。章节范围、卷名、地图名和时间顺序只能用于定位，不能单独证明 arc 存在。

本 Skill 不负责：

- 章节摘要、事件流水账或按章节切段；
- 某一条具体剧情线的完整生命周期；
- 卷名、卷序、章节区间或时间段的机械整理；
- 人物身份、性格、功能组合和关系发动机；
- 世界规则、制度、组织、资源循环和地图因果；
- 境界、技能、装备、战力与修炼成长体系；
- 金手指的输入、处理、输出、限制和成长机制；
- 可复用剧情机制、套路母型或独立事件链；
- 逐章 reader emotion、情绪词统计或角色心情分析；
- 可直接入库的正式 arc 卡、正式素材卡或总索引。

相邻专项的信息只能作为阶段接口、依赖或证据引用，不能替代对应专项完成业务对象。

## 十类阶段观察对象

### arc_boundary / 阶段边界

记录为什么这里形成新的结构阶段，以及前后阶段的目标、压力、组织方式、资源权限、地图层级、人物关系、读者期待或全局风险发生了什么级别的变化。边界必须有阶段级结构变化证据，不能只因为卷名更换、章节编号变化、日期跳转或地图切换就成立。

### arc_goal / 阶段主目标

记录该阶段承担的主推进方向、阶段任务或结构问题。arc goal 不是某一条 plotline 的单一目标，而是能够组织多条线路、人物选择、资源门槛、冲突压力或读者期待的阶段级方向。阶段可以有多个局部目标，但必须说明它们如何服务或改变阶段主目标。

### arc_pressure / 阶段持续压力

记录阶段内持续施加并维持推进的核心压力，例如资源稀缺、制度门槛、敌对势力、时间限制、关系裂缝、身份暴露、地图风险、成长债务或目标冲突。阶段压力不是敌人名单、困难列表或单场危机，必须说明它如何持续改变线路组织、选择、代价、权限或阶段方向。

### arc_progression / 阶段推进

记录阶段如何逐步升级、扩张、验证、转向、收缩或收束。推进必须说明目标、压力、线路交汇、资源权限、信息结构、人物关系、读者期待或局势如何发生连续变化，而不是把事件数量堆在一起。事件更多、地图更大、敌人更强或章节更长，不自动等于 arc progression。

### arc_turning_point / 阶段转折

记录什么变化真正改变了阶段目标、重心、路线、压力、权限、人物组织、信息结构或全局方向。普通高潮、一次胜利、一次升级、一次战斗或一个反转只有在造成阶段级后果时才可能成为 turning point；不能因为场面强度高就自动成立。

### arc_climax_or_resolution / 阶段高点或收束

记录阶段如何达到高点、完成阶段任务、失败收束、主动放弃、转向或留下结构性未决。resolution 可以成功、失败或未决，不能默认每个 arc 都以胜利高潮结束。需要区分局部剧情线 payoff 与阶段整体收束：一条线完成不代表 arc 已完成。

### arc_state_change / 阶段状态变化

记录阶段结束或发生阶段级转折后，全局发生了什么变化，例如主角或群体目标、资源、身份、关系、认知、地图、权限、风险、势力平衡、规则理解或读者期待发生了什么改变。状态变化不能只写“进入下一卷”，必须写清前后状态差异和可观察后果。

### next_arc_entry / 下一阶段入口

记录阶段状态变化如何自然打开下一阶段的目标、压力、地图、制度、关系、任务或结构问题。下一入口必须由上一阶段的状态变化、收束余波、未决任务或重心迁移产生，不能为了填结构凭空接入新地图、新敌人或新危机。

### arc_function / 阶段结构功能

记录该阶段在全书中的结构作用，例如建立、扩张、验证、升级、反转、暴露、重组、转场、收束或结局准备。功能必须由阶段内的目标、压力、推进、转折、状态变化和后续影响支撑，不能只贴“学院篇”“秘境篇”“战争篇”等表面标签。

### nested_structure / 嵌套结构

记录大 arc 与 sub-arc 的结构关系，以及子阶段如何服务、阻碍、改变或验证父阶段。大 arc 可以包含多个 sub-arc，但普通章节序列、短期事件、单条剧情线、同一地图或同一卷名不能自动成为 sub-arc。嵌套关系必须有独立阶段目标、压力、推进、收束或父阶段影响证据。

## Arc 与相似对象的硬区别

以下区别必须保持：

- arc ≠ plotline：剧情线追踪具体目标生命周期，arc 组织多个线路和阶段重心；
- arc ≠ chapter summary：章节事件列表不能证明阶段结构；
- arc ≠ volume title：卷名只是定位，不能独立划定边界；
- arc ≠ chapter range：章节区间只是覆盖范围，不等于结构阶段；
- arc ≠ time period：连续日期、年份或时间跳转没有结构变化不能成为 arc；
- arc ≠ map change：地图切换只有改变阶段目标、压力、权限或全局组织时才可能是边界证据；
- arc ≠ cultivation stage：境界突破可成为节点或门槛，不能直接当 arc；
- arc ≠ “前期/中期/后期”：空泛阶段标签没有目标、压力、转折和状态变化证据；
- arc progression ≠ event accumulation：事件越多不代表阶段越推进；
- turning point ≠ ordinary climax：普通高潮只有造成阶段级变化才可能是转折；
- arc resolution ≠ 必须成功：失败、放弃、转向和未决收束都可能成立；
- state change ≠ “进入下一卷”：必须写清阶段前后全局差异；
- nested sub-arc ≠ ordinary chapter sequence：子阶段必须承担独立结构作用。

同一章节、线路、地图或境界节点可以作为 arc 证据，但必须解释它如何改变阶段级组织，不能因为对象重叠就把相邻专项结论直接复制为 arc。

## 证据边界

证据优先级遵守上位总控契约：

1. 已通过 QA 的章节事实、剧情线状态变化、人物行为、冲突结果和阶段资料；
2. 已确认的线路、opening、世界观、修炼体系、人物功能和逐章情绪接口；
3. 已存在且可核验的分卷、阶段或地图资料，仅作定位和交叉核验；
4. BOOK DNA、章节索引和既有聚类，仅作导航；
5. 原文回查，仅在边界、转折、收束、状态变化、子阶段归属或下一入口不清时使用。

卷名、章节标题、简介、地图名、时间段、境界名、题材标签、宣传语和模型记忆不能独立支撑 arc 结论。证据不足时保留 `UNKNOWN`、`partial`、`gap` 或 `HOLD`，不能用“通常这个阶段应该……”补造阶段结构。

每条阶段结论至少应能回答：

- 为什么从这里开始一个新的阶段；
- 这个阶段要组织什么主目标和持续压力；
- 多条线路、人物、资源、信息、机制或情绪如何在阶段内被安排；
- 阶段怎样逐步推进、升级、扩张、验证、转向或收束；
- 哪个变化真正改变了阶段方向；
- 阶段高点或收束解决了什么、失败了什么、留下了什么；
- 阶段结束后全局状态发生了什么变化；
- 为什么这些变化自然打开下一阶段；
- 如果存在 nested arc，子阶段如何影响父阶段。

## 与相邻专项的分工

- `novel-plotline-miner`：负责具体剧情线的触发、目标、阻力、节点、选择、代价、兑现和生命周期；本 Skill 只观察多条线路如何在 arc 内被组织、交汇、暂停、转向、收束或改变重心。
- `novel-opening-miner`：负责前 3/5/10/20 章的开篇窗口和十二类开篇对象；本 Skill 可以引用 opening arc 或开篇阶段，但不重新执行 opening 分析。
- `novel-character-function-miner`：负责人物功能组合、关系发动机和功能变化；本 Skill 只引用人物功能变化作为阶段证据，不重做人设功能。
- `novel-chapter-emotion-miner`：负责逐章 reader emotion、蓄压、兑现和余震；本 Skill 只引用情绪曲线作为阶段节奏和承诺变化参考，不重新逐章标注情绪。
- `novel-worldbuilding-miner`：负责规则、稀缺、制度、组织和地图因果；本 Skill 只观察规则、地图或制度层级如何触发阶段边界和压力变化，不重做世界观因果链。
- `novel-cultivation-system-miner`：负责境界、技能、装备、战力和成长循环；本 Skill 只引用境界突破、资源门槛或能力验证作为阶段节点，不把成长阶段直接当 arc。
- `novel-golden-finger-miner`：负责外挂输入、处理、输出、限制和成长；本 Skill 只引用外挂权限或规则成长如何影响阶段升级，不重做金手指机制。
- `novel-plot-mechanism-miner`：负责可复用剧情机制和运行方式；本 Skill 只观察机制如何被安排、组合或冷却，不把阶段实例直接升级为机制卡。

如果某个阶段判断只有相邻专项的完整业务对象才能成立，保留接口说明、证据引用和依赖缺口，不越界代替相邻专项下结论。

## 上位契约与输入

严格遵守：

- `../../../SKILL.md`；
- `../../core/horizontal-specialist-contract.md`；
- `../../core/integration-and-qa.md`。

输入必须来自 orchestrator 冻结的批次包，至少说明目标书、章节/阶段范围、允许来源、已有专项接口、已知缺口和禁止输出。不得自行扩大书单、章节范围、来源或阶段数量，也不得用一本书的 arc 补齐另一本文本。

章节事实未通过 G1 时，不生成高置信阶段结论；上游线路、情绪或接口 QA 未通过时，只保留低置信、`gap` 或 `HOLD`，不把未确认内容写成阶段事实。

所有派生记录保持共享的 `candidate-only` 与 derived envelope 约束。具体记录字段、阶段状态、嵌套结构、聚类规则、评分方式和验证脚本已在当前 references 与 scripts 中冻结，本 Skill 不创建第二套 canonical schema。

## 运行流程

执行时按以下过程执行：

1. **冻结输入**：登记批次、目标书、章节/阶段范围、允许来源、上游 QA、已知缺口和禁止输出；
2. **识别候选边界**：从阶段目标、压力、线路组织、地图/制度权限、人物关系、成长门槛、读者期待或全局风险的结构变化中定位候选 arc；不从卷名、日期或章节编号机械切段；
3. **确认 arc goal 与 pressure**：说明阶段主推进方向和持续压力，区分阶段目标与单条剧情线目标、压力与敌人名单；
4. **提取 arc progression**：追踪阶段如何逐步升级、扩张、验证、转向或收缩，并记录多条线路、人物、资源、信息和机制的组织方式；
5. **寻找 turning point**：核对什么变化真正改变阶段目标、重心、路线、权限、压力或全局方向；
6. **判断 climax/resolution**：区分成功完成、失败收束、主动放弃、转向和未决收束，不把任何强场面自动当阶段结局；
7. **记录 state change**：说明阶段级转折或收束后全局目标、资源、身份、关系、认知、地图、权限、风险或势力状态的前后差异；
8. **确认 next arc entry**：从状态变化、收束余波、未决任务或重心迁移确认下一阶段入口；
9. **建立 nested structure**：只有子阶段有独立目标、压力、推进、收束或父阶段影响证据时才建立 nested arc；
10. **单书 QA**：检查阶段边界、目标/压力、推进、转折、收束、状态变化、下一入口、嵌套关系、相邻接口和 `UNKNOWN/gap/HOLD`；
11. **跨书比较**：全部目标书完成单书抽取和 QA 后，才比较阶段切换、升级、收束和嵌套运行方式，不按学院、比赛、秘境、战争等表面标签聚类；
12. **人工交接**：输出 candidate、证据引用、相近候选、差异边界、阶段争议和待确认决策，不自动入库。

## 横向比较原则

跨书比较的对象是阶段结构如何运行，至少比较：

- 阶段边界由什么结构变化触发；
- arc goal 如何组织多个局部目标和线路；
- arc pressure 如何持续、升级或发生重心迁移；
- progression 如何从建立走向扩张、验证、升级、反转或收束；
- turning point 如何改变阶段方向；
- climax/resolution 如何处理成功、失败、放弃、转向和未决；
- state change 如何改变全局并打开 next arc entry；
- nested arc 如何服务、阻碍、改变或验证父 arc；
- opening、人物、情绪、世界、修炼、金手指和机制接口怎样被阶段结构组织。

“都有学院篇”“都有比赛篇”“都有秘境篇”“都有战争篇”“都有城市篇”不能单独支撑近邻或聚类。必须比较阶段边界、目标/压力、推进、转折、收束、状态变化、下一入口和嵌套关系。证据不足时使用 `insufficient_evidence` 或 `HOLD`，不强行归类。

## 交付、状态与写入边界

默认输出位置（仅在用户授权后落盘）：

```text
素材库/DNA素材/08_篇章结构/per_book/
素材库/DNA素材/08_篇章结构/candidate/
素材库/DNA素材/08_篇章结构/qa/
```


每个专项批次固定规划五类交付：

1. `per_book`：单书 arc 边界、目标、压力、推进、转折、收束、状态变化、下一入口和 nested 证据包；
2. `nearest_neighbors`：按阶段结构运行方式比较的近邻记录；
3. `clusters`：阶段结构及其变体的聚类候选；
4. `qa`：阶段边界、证据覆盖、结构推进、嵌套关系、重复和阻断项；
5. `handoff`：交给人工审核的 candidate、证据引用、相近候选和决策点。

必须遵守：

- 所有专项结果只能是 `candidate`；不得生成或升级为 `active`、`deprecated` 或正式素材卡；
- `UNKNOWN`、`partial`、`gap`、`HOLD` 和 `FAIL` 必须显式保留；
- `nearest_neighbors` 与 `clusters` 必须等待全部目标书完成单书抽取和 QA，并通过 cross-book completion gate；
- 不写正式素材库、总索引、章节事实、分卷正式资料或其它正式产物；
- 不根据卷名、章节名、简介、地图名、境界名或题材标签补造 arc；
- 不修改相邻专项的 schema、索引、情绪记录或正式候选；
- 任何状态升级、schema 变更、nested 关系确认、跨专项合并或正式入库都交给上位总控和人工审核。

## 禁止事项

- 把章节摘要、章节范围、时间段或卷名直接当成 arc；
- 因为地图变化、境界突破、敌人升级或新组织出现就自动划定新阶段；
- 把单条 plotline 的目标、高潮或 payoff 直接当成 arc goal 或 arc resolution；
- 把阶段内事件数量、战斗数量或场景规模直接当作 progression；
- 把普通高潮、升级、胜利、反转或资源到账自动当 turning point；
- 把每个阶段都强行写成成功胜利，不保留失败、放弃、转向或未决收束；
- 把“进入下一卷”当作 state change，不说明全局前后差异；
- 把新地图、新敌人或新任务凭空接成 next arc entry；
- 把章节序列、短期事件、共享地图或一条线路自动升级为 nested sub-arc；
- 从卷名、章节名、简介、地图名、境界名、题材标签或模型记忆推断阶段结构；
- 用相邻专项的完整人物、线路、世界、修炼、金手指、开篇、情绪或机制对象填充 arc；
- 在所有目标书完成前建立跨书近邻或聚类；
- 把单书阶段候选写成 `active`、`deprecated` 或正式素材卡；
- 为了填满 arc 字段补造阶段目标、压力、转折、收束、状态变化或下一入口证据。

## 交付前验收

每次交付前至少确认：

1. `arc_boundary` 有结构变化证据，不由卷名、时间、地图或章节范围单独决定；
2. `arc_goal` 与单条剧情线目标分离；
3. `arc_pressure` 记录持续压力及其阶段作用，不是敌人名单；
4. `arc_progression` 描述升级、扩张、验证、转向或收束，不是事件列表；
5. `arc_turning_point` 会造成阶段级方向、重心、权限、压力或全局变化；
6. `arc_climax_or_resolution` 支持成功、失败、放弃、转向和未决收束；
7. `arc_state_change` 与 `next_arc_entry` 独立且可追溯；
8. `arc_function` 有全书结构作用证据，不由学院、秘境、战争等表面名称决定；
9. `nested_structure` 需要独立子阶段结构作用证据，不能把章节序列自动变成 sub-arc；
10. 与 plotline、opening、character-function、chapter-emotion、worldbuilding、cultivation、golden-finger、plot-mechanism 的边界没有职责泄漏；
11. 五类交付、derived envelope、candidate-only、UNKNOWN/partial/gap/HOLD 和 cross-book completion gate 均由当前 schema、validator 与交付流程承接；
12. 本文件不提前定义完整 schema 字段、量化评分、固定阶段数量或卷级排名；
13. 没有写入正式素材库、总索引或其它正式资料的路径。

本文件冻结 arc-structure 专项的职责、十类阶段观察对象、结构边界、嵌套概念、证据边界、相邻分工、输入输出原则和运行流程；具体记录字段、阶段状态、聚类规则、QA 脚本和 validator 以当前 references 与 scripts 为准。
