# 剧情线横向拆解器

## 模式路由

- 单书抽取：先读取 [schema.md](references/schema.md)。
- 横向近邻、聚类与 QA：再读取 [clustering-and-qa.md](references/clustering-and-qa.md)。
- 结构校验：运行 `python scripts/validate_outputs.py <jsonl或目录> --kind <per_book|nearest_neighbor|cluster|qa|handoff|gap>`；跨书必须额外提供 `--expected-books`、`--all-books-complete` 和 `--completion-manifest <per_book/gap.jsonl>`。

## 单一职责

本 Skill 不把章节事件简单串起来，而只回答：

> 一条具体剧情线为什么启动、追求什么、被什么阻碍、经历哪些关键选择与代价、如何兑现或失败、状态如何变化，并怎样打开下一入口？

核心生命周期固定为：

`触发 → 目标 → 阻力 → 节点 → 选择 → 代价 → 兑现 → 状态变化 → 下一入口`

一条有效的剧情线候选，必须能够回到章节或阶段证据，并说明线路在上述链条中的推进、停滞、转向、兑现、失败或继续扩展。不能把事件数量、章节篇幅、人物出场、升级结果或连续战斗本身当成剧情线。

本 Skill 不负责：

- 章节摘要、事件流水账或单纯的时间顺序整理；
- 分卷、阶段、地图和宏观篇章结构；
- 人物身份、性格、功能组合和关系发动机；
- 可复用剧情机制、套路母型或独立事件链；
- 世界规则、制度、组织和资源分配体系；
- 境界、技能、装备、战力和成长循环；
- 金手指的输入、处理、输出、限制和成长机制；
- 章节读者情绪、蓄压、兑现强度和情绪余震本身；
- 可直接入库的正式剧情线卡或素材卡。

相关信息只能作为接口、依赖或证据引用，不能替代对应专项。

## 九段生命周期

### trigger / 触发

记录为什么这条线真正开始或被唤醒，必须是章节或阶段中的实际启动事件、承诺、危机、目标暴露、任务接入、关系变化或资源门槛。背景设定第一次出现、书名、简介或人物早已有的愿望不能自动算触发。

### goal / 目标

记录人物或主角当前试图达成的、可追踪的线路目标。目标必须能够在后续被推进、阻碍、改变、兑现、失败或放弃，不是“变强”“获得认可”“活下去”等脱离线路范围的抽象愿望，除非章节证据已经把它具体化为当前线路目标。

### resistance / 阻力

记录什么持续阻止目标完成，或迫使线路改变推进方式。阻力可以来自人物、资源、信息、制度、规则、时间、风险、目标冲突、身份限制或环境，但必须真实改变推进、资源、信息、风险或选择，不能只列敌人、困难或场景名词。

### nodes / 节点

只记录真正改变线路状态、信息、资源门槛、方向、权限、关系、风险或阶段的关键节点。节点不是所有章节事件，也不是每场战斗；普通移动、重复训练、无状态变化的对话和背景说明不能为了填满线路而升级为节点。

### choices / 选择

记录人物或主角在存在替代行动、取舍、不同目标优先级或不同风险路径时作出的可观察选择。选择必须能说明选了什么、放弃或延后了什么，以及它如何影响后续线路。没有真实选择空间时，不得把被动发生的结果包装成选择。

### costs / 代价

记录推进或选择实际付出的可观察代价，例如资源消耗、关系损失、身份暴露、信息丢失、风险上升、目标延后、承诺债务、行动窗口缩小或其它后续约束。普通结果、战斗结束、拿到奖励或剧情自然推进不能自动叫代价。

### payoff / 兑现

记录前置目标、承诺或悬而未决的问题获得结果。兑现不是“发生高潮”，也不是任何战斗胜利、升级、击杀或拿到资源。

升级、击杀、战斗胜利、获得资源只有在真实完成该线路的前置目标、承诺或未决问题时，才可以作为线路兑现的一部分；否则只能记录为线路中的结果、节点、资源变化或接口证据。

没有前置目标、承诺或未决问题的结果，不能伪装成 payoff。

### state_change / 状态变化

记录兑现或失败之后，人物、关系、资源、身份、认知、风险、目标、局势、权限或线路自身实际发生了什么改变。状态变化必须独立于 payoff：结果说明“兑现了什么”，状态变化说明“兑现或失败后世界和人物变成什么样”。

### next_entry / 下一入口

记录状态变化如何打开下一阶段目标、阻力、任务、选择、兑现窗口或新子线入口。下一入口必须来自上一段真实状态变化，不能为了制造悬念凭空追加新危机，也不能把同一个 payoff 重复写成 next_entry。

`payoff`、`state_change` 和 `next_entry` 三者必须分开：

`前置目标得到结果 → 线路状态发生改变 → 新的推进入口被打开`

## 事件与剧情线的硬边界

以下对象不能自动等同于 plotline：

- 事件序列 ≠ plotline；
- 章节摘要 ≠ plotline；
- 人物出场线 ≠ plotline；
- 升级记录 ≠ plotline；
- 连续战斗 ≠ 自动 plotline；
- 有结果的单个事件 ≠ 自动 payoff；
- 有悬念的结尾 ≠ 自动 next_entry；
- 有冲突的场景 ≠ 自动 resistance；
- 有选择字样的叙述 ≠ 自动 choice。

同一目标下的多个事件可以属于同一条线路；目标发生根本改变时，要根据新旧目标、承诺、阻力、节点和状态变化判断是原线路的阶段转向、父子线关系，还是新线路，不能按章节数量机械拆分，也不能为了减少线路数量强行合并。

## 生命周期状态的概念边界

本 Skill 只冻结概念，不提前冻结 schema 的正式字段名或受控枚举。后续分析必须能够区分：

- 未启动；
- 已启动；
- 推进中；
- 暂缓；
- 转向；
- 完成或兑现；
- 失败；
- 主动放弃；
- 未知或证据不足。

这些概念必须有章节或阶段证据。不能用一个模糊的“关闭”把成功兑现、失败收束和主动放弃混为一类。具体字段和枚举以当前 `references/schema.md` 为准。

## 父线与子线

长期主线可以拥有短期子线，但本文件只冻结概念关系，不定义完整字段结构：

- 子线必须说明它服务、阻碍或改变哪条父线；
- 子线可以成为父线的节点、代价、资源入口、信息入口或下一入口；
- 子线完成不等于父线完成；
- 父线暂停不等于所有子线自动暂停；
- 父线与子线的推进状态、目标、代价和兑现必须分别取证；
- 不能因为几条线共享人物、地点或敌人就自动判定为父子关系；
- 不能把所有短期事件都升级为独立子线。

## 证据边界

证据优先级遵守上位总控契约：

1. 已通过 QA 的章节事实、事件结果和人物选择；
2. 已确认的阶段、篇章或线路资料中与具体线路生命周期直接相关的证据；
3. 已存在且可核验的读者情绪 overlay，仅作为线路效果或兑现反馈的辅助接口；
4. BOOK DNA、章节索引和既有聚类，仅作定位和交叉核验；
5. 原文回查，只用于确认触发、目标、阻力、节点、选择、代价、兑现、状态变化、下一入口或父子线归属。

书名、简介、题材标签、宣传语、人物名字、章节标题和模型记忆不能独立支撑剧情线结论。证据不足时保留 `UNKNOWN`、`partial`、`gap` 或 `HOLD`，不能用常识补造目标、阻力、选择、代价、兑现或下一入口。

每条剧情线结论优先回到以下可观察证据：

- 哪个事件真正启动或唤醒了这条线；
- 谁在追求什么具体目标；
- 什么阻力持续改变推进；
- 哪些节点真正改变了线路状态；
- 人物有哪些真实替代选择和取舍；
- 选择或推进带来了什么后续代价；
- 哪个前置目标、承诺或未决问题得到兑现或失败结果；
- 兑现/失败后人物、关系、资源、身份、认知、风险、目标或局势如何改变；
- 状态变化如何打开下一阶段或子线入口。

## 与相邻专项的分工

- `novel-character-function-miner`：负责人物如何推动、阻断、验证或改变线路；本 Skill 只引用人物作用，不重新做人设功能卡或关系发动机。
- `novel-arc-structure-miner`：负责阶段、分卷、地图和宏观结构；本 Skill 只追踪一条线路在这些阶段中的生命周期，不定义阶段结构。
- `novel-plot-mechanism-miner`：负责可复用的剧情机制和运行方式；本 Skill 负责本书这条具体线路如何使用、推进和收束，不把一次线路实例直接升格为机制卡。
- `novel-opening-miner`：负责前 3/5/10/20 章的开篇组织；本 Skill 只提供开篇期间已经开启的线路事实，不重做开篇窗口母型。
- `novel-cultivation-system-miner`：负责境界、技能、装备、战力和成长循环；本 Skill 只记录“为什么当前线路要求成长”以及成长在该线中的目标、门槛、选择或代价作用。
- `novel-worldbuilding-miner`：负责世界规则、组织、制度、资源循环和地图约束；本 Skill 只记录这些约束怎样进入具体线路，成为阻力、权限、资源入口或状态变化。
- `novel-golden-finger-miner`：负责外挂输入、处理、输出、限制和成长；本 Skill 只记录外挂何时改变线路目标、选择、代价、兑现或结果，不复制金手指机制。
- `novel-chapter-emotion-miner`：负责章节读者情绪、蓄压、兑现和余震；本 Skill 可以引用已有 reader-emotion overlay 作为线路效果证据，但不能把人物心情或单章情绪波动直接当线路状态。

如果一个结论需要相邻专项才能成立，保留 interface/evidence reference 和依赖说明，不越界代替相邻专项完成结论。

## 上位契约与输入

严格遵守：

- `../../../SKILL.md`；
- `../../core/horizontal-specialist-contract.md`；
- `../../core/integration-and-qa.md`。

输入严格来自 orchestrator 冻结的批次包。不得自行扩大书单、章节范围、来源、线路名单或输出范围，也不得用一本书的线路替另一本文本补齐缺口。

输入至少应说明目标书、章节/阶段范围、允许来源、已知缺口、情绪 overlay 接口和禁止输出。缺少必要证据时停止升级结论，输出 `gap` 或 `HOLD`。

所有派生记录必须使用共享 derived envelope，状态保持 `candidate-only`。具体记录字段、生命周期枚举、父子线结构和聚类规则在后续专项文件中单独冻结；本文件不提前定义完整 schema。

## 运行流程

执行时按以下过程执行：

1. **冻结范围**：登记批次、目标书、章节/阶段范围、允许来源、已知缺口和禁止输出；
2. **识别候选线路**：从实际目标、承诺、任务接入、危机、关系变化、资源门槛或未决问题中定位可能的线路，不按章节事件数量建线；
3. **确认 trigger / goal / resistance**：为每条候选线确认真实触发、可追踪目标和持续阻力，缺一时保留 `UNKNOWN` 或 `gap`；
4. **筛选状态改变节点**：只保留会改变线路状态、信息、资源、方向、关系、风险、权限或阶段的节点；
5. **提取 choice / cost**：确认真实替代路径、人物选择、放弃项和可观察代价；被动事件不能冒充选择，普通结果不能冒充代价；
6. **核对 payoff**：检查兑现是否对应前置目标、承诺或未决问题，区分普通结果、升级、击杀、资源获得与真正线路兑现；
7. **记录 state_change / next_entry**：独立记录兑现或失败后的状态变化，以及该变化打开的下一目标、阻力、选择或子线入口；
8. **建立父子线关系**：只有证据支持服务、阻碍或改变关系时，才建立父线与子线的概念关联；不提前设计字段；
9. **单书 QA**：检查九段链条、证据回溯、事件与线路边界、父子线关系、重复线路、UNKNOWN/gap/HOLD 和跨专项接口；
10. **跨书比较**：只有全部目标书完成单书抽取和 QA 后，才按线路运行结构和生命周期生成 `nearest_neighbors` 与 `clusters`；
11. **人工交接**：输出 candidate、证据引用、相近候选、差异边界、生命周期争议和待决策项，不自动入库。

支持多书批量时，书籍与分片必须互不重叠；先独立完成每本书的线路证据包，再在全批次完成后横向比较。任一本书证据不足，只保留该书的 `gap`，不使用其它书的线路补齐。

## 横向比较原则

跨书比较的是线路如何运行，而不是表面题材或线路名称。至少比较：

- 线路由什么触发，以及触发如何转化为具体目标；
- 目标如何生成阻力、节点和真实选择；
- 代价如何改变资源、关系、身份、风险、认知或目标；
- payoff 如何兑现前置目标、承诺或未决问题；
- state_change 如何改变线路阶段和人物状态；
- next_entry 如何打开下一阶段、父线或子线；
- 父线与子线如何依赖、服务、阻碍或互相改变；
- 线路如何暂停、转向、完成、失败、放弃或保持未决；
- 线路与人物功能、世界约束、成长系统、金手指和读者情绪 overlay 的接口。

“都有复仇线”“都有升级线”“都有学院线”“都有比赛线”“都有感情线”“都有救人任务”不能单独支撑近邻或聚类。必须说明九段运行链、状态变化、下一入口和差异边界。证据不足时使用 `insufficient_evidence` 或 `HOLD`，不强行归类。

## 交付、状态与写入边界

默认输出位置（仅在用户授权后落盘）：

```text
素材库/DNA素材/06_主线与支线/per_book/
素材库/DNA素材/06_主线与支线/candidate/
素材库/DNA素材/06_主线与支线/qa/
```


每个专项批次固定规划五类交付：

1. `per_book`：单书具体剧情线、九段生命周期、父子线关系和接口证据包；
2. `nearest_neighbors`：按线路运行结构和生命周期比较的近邻记录；
3. `clusters`：线路运行方式及其变体的聚类候选；
4. `qa`：生命周期证据、兑现边界、父子线、跨专项接口和阻断项；
5. `handoff`：交给人工审核的 candidate、证据引用、相近候选和待决策项。

必须遵守：

- 所有专项结果只能是 `candidate`；不得生成或升级为 `active`、`deprecated` 或正式素材卡；
- `UNKNOWN`、`partial`、`gap`、`HOLD` 和 `FAIL` 必须显式保留；
- `nearest_neighbors` 和 `clusters` 必须等待全部目标书完成单书抽取和 QA，并通过 cross-book completion gate；
- 不写正式素材库、总索引、章节事实、线路正式资料或其它正式产物；
- 不根据书名、简介、标题、人物名字或题材标签补造线路；
- 不修改相邻专项的 schema、索引、情绪记录或正式候选；
- 任何状态升级、正式入库、schema 变更、父子线确认或跨专项合并，都交给上位总控和人工审核。

## 禁止事项

- 把连续事件按时间排列就称为剧情线；
- 把章节摘要、分卷梗概、人物出场线或升级记录直接当剧情线；
- 把敌人列表、地点列表、战斗列表或任务列表直接当阻力或线路；
- 把发生高潮、击杀、升级、战斗胜利或获得资源直接当 payoff；
- 没有前置目标、承诺或未决问题时伪造兑现；
- 把普通结果、剧情推进或资源变化包装成 cost；
- 把被动发生的事情包装成 choice；
- 把所有章节事件都升级为 nodes；
- 把 payoff、state_change 和 next_entry 合并成一句模糊结论；
- 把父线完成、暂停或失败自动套用到所有子线；
- 从书名、简介、标签、人物名字、章节标题或模型记忆推断线路；
- 在所有目标书完成前建立跨书近邻或聚类；
- 把单书线路候选写成 `active`、`deprecated` 或正式素材卡；
- 为了填满九段链条而补造目标、阻力、选择、代价、兑现、状态变化或下一入口证据。

## 交付前验收

每次交付前至少确认：

1. 九段生命周期明确分离：trigger、goal、resistance、nodes、choices、costs、payoff、state_change、next_entry；
2. 事件序列、章节摘要、人物出场、升级记录和连续战斗不会自动生成 plotline；
3. node 只保留真正改变线路状态的节点；
4. choice 具备真实替代路径或取舍；
5. cost 是可观察代价；
6. payoff 对应前置目标、承诺或未决问题；
7. 升级、击杀、战斗胜利和资源获得只有在完成线路前置目标时才可能成为 payoff；
8. state_change 与 next_entry 独立且可追溯；
9. 生命周期概念覆盖未启动、启动、推进、暂缓、转向、完成、失败、放弃和未知，但正式枚举后置到 schema；
10. 父线/子线关系、子线完成与父线完成、父线暂停与子线暂停均不被混同；
11. 与 character-function、arc-structure、plot-mechanism、opening、cultivation、worldbuilding、golden-finger、chapter-emotion 的边界没有职责泄漏；
12. 五类交付、derived envelope、candidate-only、UNKNOWN/gap/HOLD 和 cross-book completion gate 均由当前 schema、validator 与交付流程承接；
13. 跨书比较基于线路运行结构和生命周期，不基于复仇、升级、学院、比赛、感情或救人等表面标签；
14. 本文件不偷偷形成完整 schema，不提前冻结 lifecycle 枚举或 parent-child 字段结构。
