# 逐章读者情绪拆解器

## 模式路由

- canonical 逐章记录：先读取 [references/schema.md](references/schema.md)，其字段唯一服从总控的 `chapter-emotion-schema.md`。
- 承诺追踪、节奏审计与横向候选：再读取 [references/clustering-and-qa.md](references/clustering-and-qa.md)。
- 结构校验：运行 `python scripts/validate_outputs.py <jsonl> --kind canonical --expected-book <BOOK_ID> --expected-range <起章-止章>`；跨书派生记录另加 `--all-books-complete`、`--expected-books` 和 `--completion-manifest`。

## 单一任务

本 Skill 只回答一个问题：作者如何让读者在每一章经历期待、蓄压、转折、兑现和余震。

它是横向专项的共同情绪底座，负责：

- 为每个目标章节生成一条读者情绪覆盖记录；
- 区分读者情绪与角色心情；
- 追踪跨章节承诺的开启、延迟和回收；
- 在单书章节覆盖完成后检查缺章、重复章和节奏疲劳；
- 为后续世界观、修炼体系、人物、线路、开篇、篇章和剧情机制专项提供情绪证据。

本 Skill 不负责完整章节事实拆解、世界观母型、修炼体系母型、人物卡、主支线卡、开篇母型、篇章母型、剧情机制卡或正式素材入库。

## 权威 Schema 与契约

单章 JSONL 必须直接采用并在运行时读取：

`skills/novel-dna-orchestrator/references/chapter-emotion-schema.md`

禁止在本 Skill 中复制一份可变的情绪字段表，禁止新增 `emotion_curve`、`reader_feeling`、`payoff_score` 等平行字段。Schema 中的字段、枚举、唯一性、证据要求和 `schema_version` 以该文件为唯一权威。

专项输入输出和状态边界遵守：

- `skills/novel-dna-orchestrator/references/horizontal-specialist-contract.md`
- `skills/novel-dna-orchestrator/references/integration-and-qa.md`

本 Skill 只能生成 `candidate` 记录，不能生成或升级为 `active`。正式素材审核仍由素材整理流程负责。

## 输入包

总控必须传入并冻结以下字段；本 Skill 不自行扩大书单、章节范围或来源：

```yaml
batch_id:
specialty: novel-chapter-emotion-miner
book_ids:
allowed_sources:
chapter_ranges:
emotion_overlay_paths:
output_root:
forbidden_outputs:
known_gaps:
```

优先使用以下证据顺序：

1. 已通过 QA 的章节事实；
2. 已存在且可核验的章节标题、爽点、信息差、状态变化和章末钩子字段；
3. 阶段或线路资料，仅用于确认承诺窗口和线路变化；
4. 原文回查，仅在章节归属、动作证据或承诺是否兑现不清时使用。

BOOK DNA、书名、简介和模型记忆只能作为导航，不能独立支撑情绪结论。来源缺失、正文不可读或证据不足时记录 `UNKNOWN` 或 `gap`，不得猜测。

## 核心判断规则

1. 一章只指定一个主读者情绪，辅情绪不超过两个；不要把“主角愤怒”直接写成“读者愤怒”。
2. 情绪对象必须明确：读者在期待、担心、愤怒、心疼、惊奇或获得爽感的对象是什么。
3. 期待必须能回到前置事件、目标、风险、信息缺口或已开启承诺。
4. 没有前置期待时，不得标记强兑现。
5. 升级、击杀、获奖、获得资源只是事件结果；没有公开结果、他人反应、关系动作、选择验证、代价回响或状态改变时，不自动算情绪兑现。
6. `promise_opened` 与 `promise_paid` 使用短而稳定的可识别名称；同一承诺在后续章节沿用相同名称。只在正文或可靠章节证据支持时开启或回收。
7. 章末钩子必须来自真实的状态变化、目标、风险或信息缺口，不能用机械截断充当钩子。
8. `pressure_level` 只比较同一本书的相邻章节，不跨书比较绝对强度。
9. `source_fingerprint` 能生成时使用真实 SHA-256；无法生成时写 `UNAVAILABLE`，并在批次 QA 中说明原因，不能伪造。
10. 章节记录必须保持 `(book_id, chapter)` 与 `record_id` 唯一；章节标题混乱时以 `chapter_ref` 作为稳定锚点。

## 运行流程

### 1. 冻结范围

读取输入包，登记每本书的目标章节范围、排除章节、已知缺口和来源 QA 状态。若章节事实未通过 G1，不生成高置信情绪聚合；只保留可定位的缺口或低置信记录。

### 2. 逐章抽取

对每个目标章节生成一条严格符合现有 `chapter-emotion-schema` 的 JSONL 记录，至少依据章节证据判断：章节作用、主辅读者情绪、情绪对象、期待来源、压力与转折、兑现级别、可见兑现证据、余震、章末余味、钩子、承诺变化和推进线路。

不得把多个章节合并成一条单章记录，也不得为填满字段把推测写成事实。确实没有兑现时使用 Schema 允许的“继续蓄压”级别，并解释期待被推向何处。

### 3. 单书覆盖 QA

章节抽取完成后，按冻结范围执行：

- 缺章检查：目标范围内每章都有记录，或进入明确的 `gap` 清单；
- 重复章检查：章节号、`chapter_ref`、`record_id` 和来源指纹不能无解释重复；
- 必填与枚举检查：交给验证脚本，不以“看起来像 JSON”代替校验；
- 证据检查：每条记录能回到章节或阶段位置，HOLD/FAIL 不计入可用覆盖；
- 承诺一致性检查：开启、延迟、回收的名称、证据和章节窗口可追踪；
- 角色心情隔离检查：不能用角色状态字段代替读者情绪字段。

### 4. 承诺账本

从通过 QA 的章节记录汇总承诺生命周期：首次开启章节、后续蓄压或加压、转折、首次兑现章节、兑现证据、余震和仍未回收状态。无法确认回收时保持开放或标记 `UNKNOWN`，不强行关闭。

### 5. 每十章节奏审计

按每 10 章或自然阶段生成一次审计；审计只记录问题和证据，不反向修改原章节事实。至少检查：

- 是否连续五章以上主情绪和兑现方式高度重复；
- 是否长时间蓄压而没有合理兑现窗口；
- 是否连续强兑现导致情绪麻木；
- 强兑现后是否出现关系、身份、资源、认知、目标或风险余震；
- 已开启承诺是否在合理窗口回收；
- 章末钩子是否连续同形；
- 章节缺口、重复记录和 HOLD/FAIL 是否影响结论。

### 6. 跨书交付

所有目标书的逐章抽取和单书 QA 完成前，禁止建立跨书情绪聚类。完成后才可交付统一接口：

- `per_book`：每本书的章节情绪覆盖、承诺追踪和节奏审计；
- `nearest_neighbors`：按情绪运行方式、蓄压—兑现结构和证据寻找近邻；
- `clusters`：大类、母型、子型和变体候选，全部标记 `candidate`；
- `qa`：覆盖率、缺章、重复章、UNKNOWN、争议和证据缺口；
- `handoff`：交给人工审核的候选与待决策项。

不要以情绪词相同就合并母型；必须比较期待来源、蓄压方式、兑现证据、余震和后续状态变化。单书模式只能产出单书候选，不能直接升级为跨书高频母型。

## 输出位置与写入边界

默认输出根目录由输入包的 `output_root` 决定；项目默认位置为：

```text
素材库/DNA素材/01_章节情绪/<BOOK_ID>/chapter_emotion.jsonl
素材库/DNA素材/01_章节情绪/<BOOK_ID>/rhythm_audit.md
```

章节 JSONL 中不得混入未被既有 Schema 定义的字段。批次 QA、承诺追踪和审计可以使用各自的报告结构，但必须带书籍、章节范围、证据路径、状态和缺口，且不能伪装成新的章节情绪 Schema。

制作或运行本 Skill 阶段不得修改原章节事实、正式素材卡、总索引或其他专项的正式产物。任何需要覆盖既有文件的操作都必须先获得用户明确授权，并报告准确路径、范围和风险。

## 禁止事项

- 根据书名、简介或单句卖点猜测读者情绪；
- 把角色心情、作者意图或读者可能感受混为同一字段；
- 复制并改造 `chapter-emotion-schema.md`；
- 使用无前置期待的“强兑现”填充爽点；
- 将升级、击杀、奖励、资源到账自动计为情绪兑现；
- 把机械断章标记为钩子；
- 缺证据时补造章节、承诺、回收或情绪强度；
- 章节范围未完成时建立正式跨书母型；
- 让本 Skill 顺手生成世界观、修炼、人物、线路、开篇、篇章或剧情机制正式卡；
- 写入 `active`、`deprecated` 或正式素材库；
- 为了通过字段校验而修改源章节事实。

## 验收标准

完成一个批次前必须确认：

1. 目标范围每章都有一条记录或可定位的 `gap`；
2. 单章记录严格遵守现有 Schema，字段和枚举没有漂移；
3. `(book_id, chapter)`、`chapter_ref` 和 `record_id` 的唯一性通过验证；
4. 缺章、重复章、承诺生命周期和每 10 章节奏审计均有结果；
5. 情绪结论能回到章节或阶段证据；
6. HOLD/FAIL、UNKNOWN 和 `UNAVAILABLE` 被如实隔离；
7. 交付包包含 `per_book`、`nearest_neighbors`、`clusters`、`qa`、`handoff`；
8. 所有专项产物均保持 `candidate`，没有擅自写入正式素材库；
9. 运行验证脚本并通过人工抽查；至少用两本差异明显的书确认“相同的情绪运行方式”和“只是表面情绪词相同”的情况能够区分。

## 与后续专项的接口

后续专项可以读取本 Skill 产生的情绪覆盖和节奏审计，但必须保留原始章节证据与情绪记录的引用关系：

- 世界观、修炼体系：说明规则或成长如何制造期待、压力、验证和兑现；
- 人物与关系：说明关系动作如何改变读者情绪，而不是只贴性格标签；
- 主线与支线：说明线路承诺何时启动、交汇和阶段性兑现；
- 开篇与篇章：说明窗口内的情绪承诺、蓄压和阶段闭环；
- 剧情机制：说明可复用的情绪运行链，但不得把本 Skill 的单书记录直接当成母型。

所有下游抽象仍须回到章节或阶段证据，并继续遵守总控的 `candidate → active` 权限边界。
