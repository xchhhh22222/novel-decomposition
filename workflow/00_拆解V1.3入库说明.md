# 拆解 V1.3 入库说明

本目录是新拆书成果的统一收件箱，不是正式素材库。完整拆解先落在这里，再经过证据审计、原子化、查重和人工确认后，按类型迁入共享素材库。

## 核心原则

1. 完整拆解包永久保留，作为来源证据，不直接混入正式套路卡。
2. “整体资料”和“可迁移内容”必须分层。只有单一机制、来源可追溯、情绪链完整的迁移候选，才进入正式入库审核。
3. 女主人物卡、长线反派卡、大故事线、单书 DNA 等高层资产，优先进入对应的 DNA 候选库，不强行改造成套路卡。
4. 正式套路卡执行一卡一机制，并依次给出 `NEW / MERGE / SPLIT / HOLD` 结论。
5. 未经用户确认，不写入 `素材库/套路素材/`，不覆盖正式索引，不删除原始拆解。

## 每批目录

从 `_模板/` 复制一份，以 `BATCH_日期_书名或批次名` 命名：

```text
BATCH_YYYYMMDD_名称/
├─ manifest.json
├─ 01_完整拆解/
├─ 02_迁移候选/
├─ 03_审核回执/
└─ 04_迁移记录/
```

## 状态流程

`received → audited → candidate_ready → awaiting_approval → migrated`

证据不足、结构冲突或无法确认边界时使用 `hold`。状态只记录进度，不能代替 QA、来源证据或用户授权。

## 操作约定

- 用户负责把完整拆解成果放入 `01_完整拆解/`。
- Codex 负责冻结输入范围、核对 QA、提取迁移候选、查重并生成审核回执。
- `02_迁移候选/` 只保存可独立审核的候选，不复制整包内容。
- `03_审核回执/` 记录来源、近邻、情绪链、原子性和 `NEW / MERGE / SPLIT / HOLD`。
- `04_迁移记录/` 只记录实际写入的目标文件、索引变化和验证结果。
- 完成迁移后仍保留 `01_完整拆解/`，不得用正式卡反向覆盖来源证据。

## 入库目标

- 原文、章节事实、整书总结：`素材库/书籍拆解/`
- 单书综合画像：`素材库/00_BOOK_DNA/`
- 逐章情绪、专项包、人物卡、大故事线：`素材库/DNA素材/`
- 审核通过的原子叙事机制：`素材库/套路素材/`
- 无法确认或等待补证：保留在本批次并标记 `hold`
