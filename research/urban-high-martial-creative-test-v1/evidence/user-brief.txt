## 三、小说基本要求

**题材：现代都市背景下的高武玄幻。**

应当符合都市高武读者对以下内容的基本期待：

- 有辨识度的现代高武社会；
- 明确、可成长、有代价的主角能力体系；
- 主角从弱势处境起步，通过行动改变自身命运；
- 能力成长、现实利益、势力竞争、人物关系相互推动；
- 存在明确的爽点、压力、选择、代价和阶段性情绪兑现；
- 能够支撑长期连载，而不是只适合写一个短篇故事。

**但不要把这些要求理解为固定剧情模板。**

不得预先假定主角必须是学生、必须遭遇退婚、必须有系统、必须被全班嘲笑、必须参加武考或必须拥有某种金手指。

是否使用这些元素，应由真实的素材检索、题材适配和原创构思决定。

主角可以有不同的身份、目标与人生困境。

尤其注意：

**不要照搬《灰穗封仓》《断钟静守》《共种议约》或其他既有研究候选的设定，只能迁移经过抽象的创作机制。**

## 四、第一步：真正使用现有素材库

必须先完成素材检索，再确定最终小说方案。

调用已有 02–09 素材检索能力，覆盖：

| 模块 | 要解决的创作问题 |
|---|---|
| 02 金手指 | 主角凭什么改变局面？能力输入、输出、限制、代价是什么？ |
| 03 世界观 | 都市高武社会为什么这样运行？谁控制资源和规则？ |
| 04 修炼体系 | 主角如何成长，修炼成果如何验证？ |
| 05 人物功能 | 哪些人物能够独立改变主角的选择和结局？ |
| 06 主线与支线 | 故事真正的长期目标与冲突是什么？ |
| 07 开篇 | 如何在开篇建立压力、期待和继续阅读的理由？ |
| 08 篇章结构 | 小高潮、大高潮以及阶段性兑现如何安排？ |
| 09 剧情机制 | 怎样让故事持续产生行动、冲突、选择和反馈？ |

每个模块应保留真实检索记录，包括：

- 来源书籍与素材 ID；
- 冻结 Git Commit；
- 来源文件、记录位置和可验证来源信息；
- 为什么适合或不适合本书；
- 哪些抽象功能可以借鉴；
- 哪些原作具体内容不能复制；
- 原创适配后，在小说哪个事件中实际发挥作用。

不能为了凑齐8个模块强行选择不兼容素材。

真实缺口允许使用 `ORIGINAL_DESIGN`，但要注明为何需要原创。

素材选择必须坚持三轴审核：

`SOURCE_QA / INTERFACE_READINESS / CURRENT_COMPATIBILITY`

如果某个金手指虽然酷炫，但会破坏人物关系、成长限制或长期冲突，必须拒绝。

## 五、第二步：自主设计一本小说

不要先写完整剧情，再回头给它补素材来源。

根据素材检索结果，模型内部可以比较2–3个原创构思方向，但**只正式交付一本推荐小说**。

必须完整建立：

**1. 小说定位**

- 书名及备选书名；
- 一句话核心卖点；
- 目标读者；
- 都市高武题材辨识度；
- 故事最核心的爽感来源；
- 与常见都市高武作品相比的差异。

**2. 主角**

- 出身与初始处境；
- 具体欲望、短期目标和长期目标；
- 人物性格与决策方式；
- 最重要的缺陷；
- 成长路径；
- 无法轻易逃避的代价。

主角必须通过选择推动剧情，不能只是等待系统发布任务。

**3. 金手指与修炼体系**

明确能力：

- 输入；
- 处理机制；
- 输出；
- 成长阶段；
- 资源消耗；
- 能力上限；
- 失败状态；
- 克制方式；
- 对后续人物关系与剧情的影响。

金手指需要带来有趣的爽点，但不能无代价解决所有难题。

**4. 世界与势力**

建立足以支撑前100章的现代高武世界，包含资源获取、职业与身份、武力体系和利益结构。

不要为了显得宏大而罗列大量势力。每个重要势力都应有实际目标、资源和行动能力。

**5. 人物关系**

设计至少三名具有独立目的的重要人物。

他们不能只是夸奖主角、提供道具、衬托主角强大。

他们的行动必须能够改变剧情。

## 六、第三步：情绪弧与爽点设计

这是本轮重点测试项。

首先明确读者为什么要追读。

不要只写：

“主角从弱变强。”

而要给出具体的情绪期待：

主角失去了什么？读者希望看到什么被改变？这种改变为什么值得等待？

建立大情绪弧与小情绪线。

小情绪线数量由故事实际需求决定，不必机械固定为四条。

每条情绪线写清楚：

- 期待；
- 压力；
- 角色行动；
- 冲突；
- 代价；
- 阶段兑现；
- 未付承诺；
- 对其他情绪线的因果影响。

爽点必须由行动和结果产生，不能只靠旁人震惊。

至少规划：

- 开篇第一个吸引读者的冲突；
- 前3章的小型期待兑现或有力反转；
- 前10章的阶段性爽点；
- 前30–50章的第一个重要高潮；
- 前80–100章的第二个重要高潮。

具体高潮位置允许因故事结构调整，不得为对齐数字硬凑事件。

保留九段 Story Spine 的因果完整性。

## 七、第四步：重点测试小说开篇

**本轮最重要的交付不是 JSON，而是实际小说开篇。**

### 必须写出前三章完整正文

每章参考2500–3500汉字，可按实际情节节奏适当调整。

要求：

**第1章**

- 开头尽快让读者接触真实矛盾；
- 有清晰的主角处境与行动；
- 高武世界通过人物行动自然呈现；
- 尽量避免开篇长篇介绍历史、等级体系与世界观；
- 章节结尾留下有价值的阅读期待。

**第2章**

- 第一章造成的后果继续发展；
- 主角必须主动采取行动；
- 让能力、人物关系或世界规则真正参与冲突；
- 不能简单重复第一章的压力。

**第3章**

- 给出一次具体的局部兑现、反转或不可逆变化；
- 新的结果必须推动下一阶段；
- 不要通过突然出现的万能能力强行解决问题。

### 开篇特别检查

检查是否存在：

- 主角行动动机不清楚；
- 配角集体降智；
- 反派专为被打脸而存在；
- 大量没有剧情作用的等级说明；
- 金手指规则前后矛盾；
- 设定过多而缺少事件；
- 章节结尾只有故弄玄虚，没有具体期待；
- 所谓爽点实际上没有改变任何人物或世界状态。

**不要让模型先给自己的小说打高分，然后据此宣布开篇成功。**

文学质量必须等待 GPT-6 与作者审核。

## 八、第五步：后续连载可行性

在前三章正文之外，提交：

- 第4–10章：逐章详细剧情大纲；
- 第11–30章：阶段性剧情与情绪线交织；
- 第31–50章：第一个重要高潮、兑现及不可逆状态变化；
- 第51–100章：第二个阶段的关键选择、爽点、资源变化和大弧接力；
- 第100章以后：只保留必要的长期承诺与接续条件。

每一阶段必须由前一阶段结果推动。

不能直接复制“遇见更强敌人→升级→击败→换地图”的循环。

未完成的大弧承诺必须记录在账本中，不能因为开启新篇章就取消。

## 九、第六步：测试素材库到底贡献了什么

这是与普通 AI 小说创作最不同的环节。

建立一份《素材贡献与失败分析报告》。

回答：

1. 最终使用了哪些真正存在的素材？
2. 哪些素材被拒绝？为什么？
3. 金手指是否因为素材库而产生了更明确的机制？
4. 世界与资源循环是否得到素材库的实际帮助？
5. 人物关系是否因某些素材功能变得更有行动力？
6. 第1–3章分别借鉴了哪些抽象的开篇功能？
7. 是否有素材不适配、证据不足或原创组合生硬的地方？
8. 如果移除一项核心素材，小说具体哪段行动、代价或兑现必须改变？

允许制作一个简短的无素材库对照方案来帮助观察，但必须保持同一创作需求；如果无法独立隔离上下文，明确说明不能据此证明素材库提高了质量。

**绝不允许用“检索了多少素材”来证明小说好看。**
